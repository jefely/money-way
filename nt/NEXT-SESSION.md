### 2.1 本地服务

双击桌面：

```text
C:\Users\Administrator\Desktop\启动NT本地服务.bat
```

或者手动：

```powershell
cd D:\myproject\money-way

```

看到下面这行就成功了：

```text
NT 本地调试: http://127.0.0.1:8080/nt/index.html?debug=1
```

- **必须走 http**，`file://` 下 `fetch('./templates/templates.html')` 会被 CORS 拦，页面白屏。

首次打开要设置本机主密码；已有账本用原密码解锁。密码只在本机，丢了只能靠加密备份。

## 7. 当前产品口径（别改错）

### 7.1 期初方向（v1.254 起）

| 账户类型 | 期初流水方向 |
|---|---|
| 资产 / 费用 / 成本 | `期初余额 → 账户` |
| 负债 / 权益 / 收入 | `账户 → 期初余额` |

- 负债欠款填正数，例如信用卡欠 193,524.03：
  `信用卡 → 期初余额  193,524.03  备注「期初」`
- 旧存档里方向录反的 `opening` 流水，`migrate` 时会自动摆正；幂等，资产不动。
- 节点设置里的「期初」金额会自动生成上述流水；不要再手工加反向行。

### 7.2 分类统计（v1.249–v1.272）

**三栏**（2026-11 定稿，`minmax(0,1.5fr) minmax(0,1fr) minmax(0,1fr)`）：
左 = 6 大分类表；中、右 = 两个**独立**的分类查询（各自输入、各自结果）。
≤900px 一屏一栏横向吸附。

1. **左栏 6 大分类**，顺序固定（2026-11 用户《统计功能规划》定稿）：
   `收入 / 负债 / 权益 / 资产 / 费用 / 成本`，从上到下，**有内容才出一张表**：
   - **六张表统一 5 列**：第 1 列 + 4 个数值列；列名随类型变，见 `core/stats-panels.js` 的 `STAT_COLS`。
     | 类型 | 第 1 列 | 增（第 3 列） | 减（第 4 列） | 第 5 列 |
     |---|---|---|---|---|
     | 收入 | 期初累计 | 本期收入（转出） | 本期退回（转入） | 期末累计 |
     | 负债 | 期初余额 | 本期新增（转出） | 本期偿还（转入） | 期末余额 |
     | 权益 | 期初余额 | 本期增加（转出） | 本期减少（转入） | 期末余额 |
     | 资产 | 期初余额 | 本期流入（转入） | 本期流出（转出） | 期末余额 |
     | 费用 | 本期累计 | 本期支出（转入） | 本期退回（转出） | **本期净出** |
     | 成本 | 期初净值 | 本期新增（转入） | 本期消耗（转出） | 期末净值 |
   - 第 1 列：五类都是「本期开始前」（A 极资产/成本 = 历史转入 − 历史转出；
     B 极收入/负债/权益 = 历史转出 − 历史转入），所以六类能并排看。
   - **费用是例外**：`本期累计` = 到**本期结束**的累计净支出（转入 − 转出），
     等于资产类的「期末」。用户要「这类到今天一共花了多少」，所以不看期初。
   - 费用没有期末：第 5 列只报本期净出，滚动关系 `本期累计 = 上期累计 + 本期净出`。
   - 数学只有两套（B 极小 / A 极大），费用是 A 极的变体 —— **别为 12 张表写 12 份公式**。
2. **节点视图**（`data-cap="summary"`，tab 文案「节点」）：和分类视图**同一个构建器**
   （`ui/stats-group-tables.js`），只换第一列（节点名）与列宽参数（六类共用 `节点汇总/列宽`）。
   口径与分类逐项一致，数据来自 `nodeStats()`。
3. **中/右栏 分类查询**：输入分类关键字或拼音首字母，
   按当前时间段列出转出方或转入方分类命中的流水 `日期 | 转出 | 转入 | 金额 | 备注`

- 只看当前选中时间段（月 / 年 / 区间 / 全部），不再混「当前余额 / 历史转出转入」。
- 全零分类默认隐藏。
- 负债按**应付口径**：转出=欠款增加，转入=欠款减少；正数=欠款，负余额=多还（显示「多还 ¥…」）。
- 期末 = 期初 + 增加 − 减少。
- **每类一张独立小表**：合计行在表头**上边**（`thead` 第一行、`<td>`），
  普通透明底、**不画竖线**、加粗 13px；合计行的**分类列放类型名**（`资产`），
  金额只留数字（没有「合计：」后缀）；**没有序号列**（手机放不下）；
  表间空 24px 无边框。
- **表宽 = 容器可用宽**（2026-11）：容器左右各留 12px，卡片与表格 `width:100%`，
  六张表宽度一致；手机 390 屏 5 列正好排满，不用横滑。
- **列宽只有两件事**：第 1 列（分类 / 节点）**各一个参数一条变量**
  （分类 `分类统计/列宽` 默认 `72`、节点 `节点统计/列宽` 默认 `108`），同类六张表读同一个值；
  后面 4 个金额列**不写宽度**，`table-layout:fixed` 自动均分剩余空间。
  **拖动是 `ui/stat-resize.js` 的专用实现**，不走 `ui/table-layout.js` 的通用那套
  （通用实现按坐标命中、不检查手柄，会把 px 钉到金额列上 → 「点表头就错乱」）。
- **字号缩放只作用于金额列**（用户 2026-11-08）：`分类统计/列标字号`（12）、
  `分类统计/数据字号`（14）两个参数驱动 `--nt-stat-head-font` / `--nt-stat-font`，
  七张统计表的**金额列**跟着收放。**第一列（分类 / 节点名）字号固定 13px，不参与缩放**，
  放不下就截断（`text-overflow: ellipsis`，全文在 `title` 里）；
  `ui/stat-fit.js` 的自动收窄也跳过第一列 —— 否则一个长节点名会把整表金额一起缩小。
- **分类查询支持拼音首字母**（v1.260）：输入 `c` 弹出 `cx 储蓄` / `rc 日常` 候选，
  点选或回车带入分类名。首字母用 `Intl.Collator('zh')` 的拼音排序算，
  没有字表（见 `core/pinyin.js`）；生僻字退回名字匹配。
- 查询面板：标题「分类查询」在左，输入框（1/3 宽）+ 清空**靠右**排列，同高 26px。

### 7.3 固定收支

- 末尾固定 **10 个空行**；空行不显示「每月 / 日期 / 金额」，整行留白。
- 只有离开整行（focusout / 失焦到行外）才创建规则，金额失焦到备注不会提前建。
- 月度固定：到日在流水里自动记账；日度固定：只在“今天”显示并带 ▲，不自动补记。
- 删除自动记账的当期流水 = 作废该期，不再自动补。
- 非分期的固定规则备注是模板备注；空就是空，不拼「第 X 期」。
- 新节点（from/to 未知名称）自动建为 **U（未定类型）**，不阻塞录入。

### 7.4 其他已定交互

- **流水查询（v1.258 / v1.259）**：转出、转入填**同一个节点** = 该节点的转出 + 转入一起列
  （一笔流水不可能自己转给自己，按「与」筛永远是 0 行）；写法不同但指向同一账户
  （名字 / 简码）也算同一节点。时间段留空 = 该节点全部流水。结果按日期升序。
  **转出/转入是回车或失焦才筛**（v1.259：实时筛太闪），简码在这时换成节点名字。
  路径页左栏的筛选框走同一套（日期/金额/备注仍即时筛）。
- 同步弹窗：日轮动态长度、月份条与保存按钮同行；窄屏不塌。
- 列宽拖动：线在列右边缘左 2px；手机表头 `touch-action: pan-y`，横向拖拽不被表格滚动抢走。
- 重复简码允许，深红提示，不阻止保存。
- 固定表对齐：名称左、金额右、账单/还款居中。
- 环图 tooltip 在指针上方。
- 建议弹层用 pointerdown 选择。

### 7.5 U 区：类型不填，决不入账（2026-11 用户裁决）

- 一条流水只有「两端账户都存在、**都有类型**、金额 > 0」才算已入账。
- 缺类型 / 断链 / 零额：写库时自动标 `status:'draft'`，不进余额、统计、环图、同步码。
- 补上类型 → 自动转正；清空类型或删账户 → 自动降级（`schema.syncPostStatus`）。
- 流水表序号给**黄色「未定类型」**标记（`markerOf` 返回 `untyped`），红色 `missing` 是缺端。
- 连带修掉：给 U 区账户改名字，不会再把它悄悄变成资产类（`updateAccount` 保留空类型）。
### 7.6 账单导入：强定位，不靠用户整理文件（2026-11）

三家导出的原文件**直接丢进来**就能用，不需要先删说明行、转编码、改表头。

| 坑 | 现在的做法 |
|---|---|
| 前面十几行说明文字 | 横扫前 60 行找表头，找不到就用「日期列 + 金额列」的形态定位 |
| 微信的日期是 Excel 序列号 `46317.44…` | `parseBillDate` 认带小数的序列号；时间从小数部分还原 |
| 支付宝/招行的 CSV 是 GBK | `decodeBytes`：BOM → UTF-8 → 出现替换字符就换 GBK |
| 招行是合并表头 + 固定列 | `fixedMap`：日期 0 / 币种 1 / 金额 2 / 摘要 6 / 对手 9 |
| 招行没有方向列 | 金额负 = 支出，正 = 收入 |
| 招行没有支付方式列 | 表头里「账号：…7912」取尾四位匹配账户；再退到用户选的「我的账户」 |

**导入窗口只填一个起始日期**（之前的记录不用再核对），其余全自动：

| 六大核心元素 | 来源 |
|---|---|
| 转出节点 / 转入节点 | 支付方式 → 我的账户；交易分类或交易对方 → 对方节点（缺的自动建） |
| 节点统计分类 | 支付宝用「交易分类」；招行用「交易摘要」；微信留给账户自己的分类 |
| 节点会计类型 | 支出 → 费用类；收入 → 收入类；花呗/借呗/白条/信用卡 → 负债类 |
| 备注分类 | 账单的「交易分类」 |
| 备注关键字 | 交易对方（商户名） |

**中性交易默认跳过**（「不计收支」、微信的 `/`）：它们不是收支，导进来只会让统计多出假流水。

**重复不跳过，只标红**（2026-11 用户定）：三个账单会有大量重复，支付宝往往是中介，
真正转出账户是它绑的那张卡。判定 = 同一天 + 同金额 + 转出或转入有一端相同（±2 小时内；时间是 00:00 视为没给时间，不参与比对）。
导入后按「日期 + 发生时间」重排，同一天的记录连续，红字行（`.nt-row-suspect`）一眼能看到，
由用户逐条删、留下需要的。**不做自动去重** —— 删哪一条只有用户知道。

### 关键字驱动的节点归类（v1.469，用户 2026-11-08 定的记账模型）

用户的模型：**账本里每个节点就是账户，每条流水就是「节点 A → 节点 B」**。
所以不存在「不算收支的转账」——还款、提现、余额宝搬钱和「卡 → 早餐」是同一等公民，
都必须进账本，否则节点余额永远对不上；统计是在**节点层面**按类型算出来的。

**导入时**（`core/bill-plan.js`）：

- **高频商户（≥ 3 次，`KEYWORD_MIN`）用商户名自成节点**（味丰源）；
  低频商户归到交易分类，商户名只进备注关键字 —— 否则 365 笔账单会长出八十个节点。
- 高频商户的关键字同时登记到**备注区**（`bill-apply.js` 调 `addNote`，分配固定 ID），
  就是用户说的「待确认分类的条目」。
- **资金流转绝不跳过**：两端都认得出 → 转账；只认出一端 → 照样落地，另一端留空
  （U 区草稿），用户在流水表里补。关键字是「还款 / 提现 / 转账 / 退款」。
- 还款的对方是信用卡：账单里给了「尾号 1234」这类标记，先按尾号匹配节点
  （`matchAccountText` 认 3 位以上数字），匹配不到就建议新建 `信用卡(1234)`（负债类），
  由 `bill-apply` 的 `toSuggest` 建出来并指向它。

**归类**（`ui/note-table.js` + `core/account-merge.js`）：

- 在备注区把关键字改成**已有节点名** → 弹「合并到已有节点？」→ 确认后
  `mergeAccountInto` 把该节点名下流水的**两端**全部改指目标，删掉临时节点；
  **流水备注关键字保留原商户名**（这钱当初是给谁的，记录还在）。
- 改成**不存在的名字** → 直接把临时节点改名（就是用户说的「新建早餐这个节点」），
  节点落在 U 区；用户设了统计分类 → 自动定会计类型（费用）→ 才进 A 区。

### 资金流转（原「中性交易」）怎么导（v1.468）

账单「收/支」列写「不计收支」（微信 `/`）的行**不是收支**，是资金在自己名下的账户之间搬。
现在默认按「账户间转账」导入，两端必须都是账本里**已有**的账户：

| 类别 | 判定 | 方向 |
|---|---|---|
| 还款 | 分类「信用借还」或说明含「还款」 | 卡 / 余额宝 → 花呗 / 借呗 |
| 退款 | 分类「退款」或说明以「退款」开头 | 原费用节点 → 退回的账户 |
| 提现 | 分类「账户存取」或说明含「提现」 | 余额 → 银行（走银行简称别名） |
| 搬钱 / 理财 | 其余 | 说明含「转出」「赎回」：说明里的账户 → 付款方式；<br>含「转入」「收款到」「理财」：付款方式 → 说明里的账户 |

**认不出方向就返回 `null`，不猜**。例：「转账到银行卡」的对方写的是本人名字，
目标账户认不出 → 跳过。猜错的代价不是少一笔，是把两个账户的余额**同时**弄错。

- 转账行 `row.dir = 'transfer'`、`row.transfer = true`，**不计入消费 / 收入合计**；
  预览里符号是 `⇄`。
- 统计口径（**v1.469 起 `neutral` 已被 `pending` 取代**）：
  `stats.transfer` = 两端都认得出的转账笔数；`stats.pending` = 只认出一端、
  另一端留空落地的笔数。**「跳过」这个状态已经没有了**。
- 实测（真实支付宝账单 365 笔 + 86 账户的真账本）：13 笔按转账导入、15 笔只认出一端
  （先落草稿），消费 / 收入仍是 `6207.74 / 14600`，没有被转账撑大。
- 2 笔 method 为空的「花呗|信用购自动还款」两端都空，会落成「缺一侧」的草稿 ——
  它们是花呗账单自带的另一条腿，建议在流水表里删掉，否则同一笔还款记两次。

### 今晚定的七条口径（后续别再改错）

1. **一切皆账户间转账**：没有「不算收支的转账」。还款、提现、余额宝搬钱和
   「卡 → 早餐」是同一等公民，都必须落到两端节点，否则余额永远对不上；
   统计是在**节点层面**按类型算出来的，不是账单层面另加一个合计。
2. **绝不自动跳过**：两头对不上就落地成草稿（U 区规则），由用户补。
   「认不出就跳过」是被明确否掉的做法。
3. **关键字驱动归类**：出现 ≥3 次（`KEYWORD_MIN`）的商户自成节点 + 进备注区；
   低频商户归交易分类，商户名只进备注关键字。用户在备注区改名 =
   合并（目标已存在）或改名（不存在），并把 `说法 → 节点名` 写进别名表。
4. **别名表是软件级的**：存在 IndexedDB 的 `aliases` key，**不进账本 state**，
   跨账本共享、重置账本不删；表里只存「说法 → 名字」，不存节点 id。
5. **备注统计只累加、不平账**：一级按关键字、二级按备注类型；不改流水、不查借贷。
6. **节点关系由用户确立**：`account.parentId`，没设就是根（**不是「未分类」**）；
   未确立时保持开放，不替用户猜；以后由大模型从模板数据里抽取关系表。
7. **备注格式**（沿用单文件版定过的）：`类型：关键字，日期 时间，内容，内容`。
   **没有类型就省掉「类型：」这一段**，写成 `关键字，日期 时间，内容，内容`
   （微信 / 招行账单没有交易分类列，走的就是这条）。只用中文冒号 + 中文逗号，
   **不要全角竖线 `｜`、不要括号**（`bill-plan.js` 的 `planOne`）。
   内容里出现的 `()`、`|` 是账单原文，不是拼接符号，别一起改掉。
