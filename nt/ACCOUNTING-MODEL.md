# 复式记账的数学本质：A/B 双极性

> 本文是 `nt/` 多文件版的**账务模型说明**。
> 它解释一件事：五种账户类型在「转出 / 转入」模型里其实只有**两种极性**。
> 术语见 [`GLOSSARY.md`](GLOSSARY.md)。

---

## 一、为什么只需要两种极性

洞穿复式记账法诞生 500 多年来，最底层的数学本质：

```
A 角色：「转入增加，转出减少」
B 角色：「转出增加，转入减少」
```

五种账户类型（资产、负债、权益、收入、费用）在计算上只分这两边。
会计学把这件事叫作「借增贷减」，本账本把它下降成**一个布尔值**。

---

## 二、A 角色：正向账户（资产型）🟢

| | |
|---|---|
| **公式** | `余额 = 期初 + 转入 − 转出` |
| **业务直觉** | 「我拥有的东西」。钱流进来（转入）我就变多，钱流出去（转出）我就变少 |
| **包含类型** | **资产类、费用类** |

**为什么费用也算正向？**

花钱相当于消耗了你的资产，是一种单向的「流出」；
在数学上它和资产是同一个方向——**转入让它变大，转出让它变小**。

---

## 三、B 角色：反向账户（负债 / 来源型）🔴

| | |
|---|---|
| **公式** | `余额 = 期初 + 转出 − 转入` |
| **业务直觉** | 「我的钱是从哪来的（欠谁 / 赚谁）」。钱借进来（转出）我的欠债就变多，我还钱（转入）欠债就变少 |
| **包含类型** | **负债类、权益类、收入类** |

**为什么收入也算反向？**

赚钱相当于你的资金来源增加；
在数学上它和负债、权益是同一个方向——**转出让它变大，转入让它变小**。

---

## 四、这个认知极其重要，因为

### 1. 代码可以「降维」

`js/core/schema.js` 里只有一行：

```javascript
export const DEBIT_TYPES = [ACCOUNT_TYPE.ASSET, ACCOUNT_TYPE.EXPENSE];
```

`balance-calculator.js` 拿它判断符号，**一处定义、全账本共用**：

```javascript
export function isDebitType(type) {
  return DEBIT_TYPES.indexOf(type) >= 0;
}

export function balanceOf(account, transactions) {
  const debit = isDebitType(account.type);
  let sum = 0;
  for (const t of transactions) {
    if (t.from_id === account.id) sum += debit ? -amount : +amount;  // 转出
    if (t.to_id   === account.id) sum += debit ? +amount : -amount;  // 转入
  }
  return { balance: round2(opening + sum) };
}
```

底层计算器**连 `if (cat === '资产类')` 都不用写**，只看那个布尔值。

### 2. 彻底解释了记账逻辑

普通人理解不了「为什么信用卡刷爆了（转出增加）余额反而变大」。

用 A/B 角色解释就极其通顺：

> 信用卡是 **B 角色（来源）**。你「转出」一笔钱去消费，
> 相当于你向银行「借来」一笔资金，所以你的欠款（余额）增加了。

### 3. 完美对应 Money Way 环状图

| 角色 | 环上的位置 | 含义 |
|---|---|---|
| **B 角色** | 左半边环：收入、负债、权益 | **水源**——钱从哪来 |
| **A 角色** | 中间 + 右半边环：资产、费用 | **管道与农田**——钱流向哪、花在哪 |

环图的排序（`CAT_ORDER`）就是按这个顺序排的：

```
收入类 → 资产类 → 费用类 → 负债类 → 权益类 → 其它
```

从水源出发，经管道，到农田，最后回到欠款与本金。

## 五、落到界面上：设置页的两个区域

账户表按角色分成两区，直接告诉用户「这个账户属于哪一边」，
**防止填错极性**：

| 区域 | 名称 | 包含类型 |
|---|---|---|
| **A** | A 我的资产/日常支出 | 资产类、费用类 |
| **B** | B 收入与本金/欠款与贷款 | 负债类、权益类、收入类 |

账户一旦落到正确的区域，加减方向就不会错——
用户不需要理解「借 / 贷」，只需要知道**这个东西是我的，还是我欠的**。

## 六、和会计科目的对照

| 本账本 | 会计学 | 借贷方向 |
|---|---|---|
| A 角色 | 借方科目 | 借增贷减 |
| B 角色 | 贷方科目 | 贷增借减 |
| 转入 | 借方发生 / 贷方发生（视科目） | 取决于科目极性 |
| 转出 | 与「转入」相反 | 取决于科目极性 |

**关键差异**：本账本不要求用户判断借贷，
只要求回答「这笔钱从哪来、到哪去」——极性由**账户类型**自动决定。

## 七、这条规则在代码里的落点

| 文件 | 职责 |
|---|---|
| `core/schema.js` | `DEBIT_TYPES` —— 唯一极性定义 |
| `core/balance-calculator.js` | `isDebitType` + `balanceOf` —— 只看布尔值 |
| `ui/account-table.js` | 设置页按 A/B 分区渲染 |
| `graph/mw-slot-calculator.js` | `CAT_ORDER` —— 环上 A/B 的排布 |
| `graph/mw-path-calculator.js` | 线宽按**转入方类型**加权（终点优先） |

> 改极性只需动 `DEBIT_TYPES` 一处；
> 任何地方出现 `if (type === '资产类')` 都是**违反本规范**的写法。
