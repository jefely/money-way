## 1. 现行设计，以及已经被换掉的说法

### 现在接受的

外观大体认可，后续修 bug 不要顺便改质感：

- 正圆。合并轮廓是外弧 + 凹桥，一条闭合路径（`unionOutline`）。
- 填充默认透明度 0.05（`脉络填充透明`）。中心渐变（`脉络核*`）和内发光、外晕是三层不同的东西。
- 内发光只在轮廓内，外晕只在轮廓外，各自可关。
- 名称、金额默认同字号，可关同步后分开。透明度、渐隐本来就分开。
- 大小：金额平方根 × 分档百分数。最小/最大直径默认不把小额夹死。

布局从 v1.566 起按窗口停靠，不再画轴线：

- 左缘错层 2 列：驻留负债和权益。收入从左缘出现。负债仍是欠款变大/变小。权益是贷方余额：半径在这笔进行中跟着变，数字仍在完成时跳。收入类没有驻留泡，`flowFractions` 的 inflow `src` 从 v1.566 起和 `dst` 用同一条并入曲线，好让权益半径有数可跟。
- 正中错层 3 列：只停资产。进来变大，出去变小，余额到 0 消失。
- 右缘错层 2 列：同一天、同一统计分类的费用和成本。圆可以在飞入末段跟着长，**数字**仍等这笔飞完才跳。
- 列号按 id 或分类名固定。成员增减不换列。让位跟着半径走，是滚动的连续函数。
- 时间：过去在上，未来在下。一屏天数把画布全高锁成若干日历日，默认 3。标尺不被镜头或空月压缩改写。
- 飞入从左缘偏下沿抛物线进入。借款、还款、互转连接真实账户。没有永久连线。
- 并入：飞泡在进度 0.72–1 收进终点圆心，半径收到 0。颈只在两圆贴上之后变粗。飞来的金额文字并入时保持，完成后才淡出。余额数字仍在完成时跳。倒放沿同一曲线分开。

## 2. 代码实际在做什么

下面描述的是 v1.566 源码，不是愿望。v1.565 的填充/描边/发光路径没有改。

### 2.1 文件

| 文件 | 职能 |

### 2.2 一笔流水变成什么

`buildLifeVein` 给每笔已入账流水一个事件：`fromId`、`toId`、`amount`、`day`（账上的日序号）、`vday`（空档压短后的视觉日）、`kind`（`classifyFlow`）、`key`（数组下标，排序用）。

`classifyFlow`（`bubble-motion.js`）按账户类型：

| kind | 典型 |
|---|---|
| `inflow` | 收入/权益 → 资产 |
| `borrow` | 负债 → 资产 |
| `spend` | 资产 → 费用/成本 |
| `charge` | 负债 → 费用/成本 |
| `repay` | 资产 → 负债 |
| `transfer` | 资产↔资产，或负债↔负债 |

方向用 `isDebitType`：资产/费用/成本借方增加；负债/权益/收入贷方增加。负债账户上，`fromId` 是这笔负债时欠款增加（借款、刷卡、期初的方向要看事件怎么生成）。画面不另造一套符号。

期初在 `js/core/opening-tx.js`：借方账户是「期初 → 账户」，贷方账户是「账户 → 期初」。开反了，欠款符号会反。

### 2.3 三种「余额」不是同一个数

| 名字 | 函数 | 代码实际做什么 |
|---|---|---|
| 账本余额 | `lifevein-model` 里按日记的存量 | 与滚动无关 |
| 半径用的数 | `stockBooks` 里的 `size` | 用 `flowFractions(kind, p)` 的 `src`/`dst` 比例。飞行过程中连续变化 |
| 标签上的数 | `stockBooks` 里的 `label` | **只有 `p >= 1` 才把整笔算进去**。0 &lt; p &lt; 1 时保持飞之前的整数笔余额 |
| `shownBalance` | 同文件导出 | 仍按比例累加，**画面节点不用它**。旧测试和任何直接调用的人还会看到滚动数字 |

飞泡自己的 `amount` 是这笔流水的全额，不插值。转账的名称被写成「转账」（`buildHome`），借款「借入」，还款「还款」，其余用分类或账户名。

节点出现的条件：`|label| ≥ 0.5`，或者有一笔 0 &lt; p &lt; 1 碰着它（`live`）。半径用 `bubbleRadius(|size|)`。`size` 还几乎是 0 时，半径函数对不足 0.5 的金额返回 2。所以一颗「还没飞完、标签仍是 0」的新账户可以是一个极小的点。这是代码行为，不是文档里的比喻。

### 2.4 谁先飞

`playLayout(model, ppd, height, winPx)`：

- 动画窗口的视觉日长度 `span = windowPx / ppd`（`windowPx` 为 0 时用 0.8×高度）。
- 事件按 `day` 再按 `key` 排序，不改账上的顺序。
- 若两端有存量账户（`account.stock`），这一笔的播放位置 = max(自然视觉日 + 已经插入的空隙, 这些账户上一次结束的位置)。上一次结束 = 上一笔起点 + `span`。
- 因此 **同一存量账户上，进度窗口首尾相接，不重叠**。不碰这些账户的另一笔可以落在重叠的滚动区间里（代码允许同时飞）。
- 多出来的空隙记在 `extras` 里，并写进 `marks`：拉开的那一段日历日不变。`playDay` 在两个相同 `day` 的刻度之间返回这个日，不插出假的下一天。
- `playSpan` 至少盖住最后一笔的起点 + `span`，拖动上限用它（`lifevein.js` 的 `setScroll`）。

`eventProgress`：日期线在动画区下沿时进度 0，往上走，走完 `windowPx` 时进度 1。不钳制，所以小于 0 还没开始，大于 1 已经结束。进度对 `scrollDay` 单调增加。同一 `scrollDay` 再算一次，输入相同则输出相同（没有帧间积分）。

**和面板不一致的地方：** `脉络同日间隔`（`dayGap`）仍由 `lifevein.js` 放进 view，`shownBalance` 仍会用它。`buildHome` **不读** `view.dayGap`。改这个旋钮目前不改变脉络画面。同日错开实际靠上面的 `span`。

### 2.5 坐标

- 世界坐标：`buildHome` 里的 `x`/`y`。停靠先算在屏幕像素上，再用 `wx`/`wy` 按**适配镜头**换回世界坐标，画的时候乘回去，左右缘仍贴窗口。用户的放大/平移是另一层 `viewZoom`，加在适配镜头外面，不把左右缘重新收进中间。
- `cameraFit` **只看 `scene.asset`**，把它们收进大约 34%–66% 的水平带，且 `s ≤ 1`。左右缘不参加这次缩小。
- 列：`dockColumns`。左 `n=2`、中 `n=3`、右 `n=2`。`slot` 来自该区全部账户 id 的排序（右缘用分类名），不是「当前看得见的第几颗」。空列宽度为 0。奇数列在 y 上错开约 0.62 倍该列最大半径。
- 一屏天数大于 0 时，费用的 y 用日历日 `e.day`，再 `wy` 到屏幕，标尺不乘 `cam.s`。
- 设备像素比：`lifevein.js` 的 `resize` 把画布像素设为 CSS 尺寸 × dpr（上限 2），`setTransform(dpr,…)`。背景 `paintField` 在 `setTransform(1,0,0,1)` 下按设备像素铺，铺完 `restore`。泡和字在镜头变换之后画。dpr 不改变世界坐标里的圆是否重合。

### 2.6 绘制顺序（填充、白线、内光、外晕必须同一条路径）

`drawBubbleStage` 对每个飞泡决定要不要和某一端做合并：进度 &lt; 0.5 且更靠近来源，则来源；≥ 0.5 且更靠近目的，则目的。若飞泡同时压进来源和目的（两边间隙都 &lt; 0），**不合并**。若还压进无关的圆（间隙 &lt; 2），也不合并。

合并时 `paintUnion`：

1. `unionAdd(parts)` 得到路径函数 `add`。
2. `paintOuterGlow`：`save`，用外包矩形减 `add()` 做 even-odd 裁切，再沿 **同一条 `add()`** 向外描。`restore`。
3. `beginPath(); add();` 然后按 `脉络填充透明` 填充。
4. `paintInnerGlow`：`save`，`add()` 后 `clip`，沿 **同一条 `add()`** 向内描。`restore`。
5. **再次** `beginPath(); add();` 然后 `stroke`。

第 5 步是 v1.565 补上的。内发光里会 `beginPath` 再描自己的一圈；若描边不重新 `add()`，当前路径可能停在辅助圆上（见第三节）。

发光中心来自 `bodyDiscs(parts, bodies)`。调用处传入的是飞泡和那一端 `[j.fly, j.dst]`，不是轮廓数组里的桥弧圆心。

`unionOutline`（`bubble-union.js`）：

- 离得远、或算不出桥：返回 `null`，调用方不画这条合并（两颗分开画）。
- 一颗含住另一颗：只返回外面那颗圆。
- 否则 `bridgeOutline`：A 的外弧、一侧凹桥、B 的外弧、另一侧凹桥。桥的圆心在两圆外侧。

单颗泡的 `orb()` 用 `circleAdd` 画填充和描边，内外发光也用这个 `circleAdd`。没有桥弧。

### 2.7 倒放

位置、半径、合并与否都是 `scrollDay` 的函数。`lifevein.js` 手指上移增大 `scrollDay`（正放），下移减小。没有速度积分，也不另开一条时钟去「慢慢吸过去」。同一进度再画，应得到同一帧。倒放把同一条曲线走回去。

`textFade(p)`：p ≤ 1 时飞来的文字不淡；p 超过 1 之后，用 `脉络字渐隐` 那段进度淡掉。飞泡身体在 p→1 时半径已经收到 0，完成后只留这行字。字的排版半径用整笔金额的半径（`labelR`），不跟着身体缩成一点。

并入几何：`melt = smooth((p-0.72)/0.28)`。飞泡圆心从弧线收到终点圆心，半径乘 `1-melt`。外推的力度也乘 `1-melt`，不再在某个 t 上突然松开。以前会跳的地方是：按可见序号 `% 列数` 重排列、间隙一小于 8px 就整段接上粗颈、进度到 1 把还没缩小的飞泡直接删掉、飞泡之间的推开在 t=0.74 停止。这几处已改成上面的连续函数。颈（`tangentBridge`）只在表面间隙小于约 1.5px 或已经重叠时存在，半径从贴上时的约 0.45px 随重叠变大。

### 2.8 标尺

`paintRuler` 占画布全高。`view.daysPer > 0` 时不乘镜头：`screenDayMarks` 按日历日从 `scroll ± daysPer/2` 排刻度，像素 = 画布高度 / 一屏天数。密到不足约 14px 仍合成「14–22」。此模式下 `lifevein.js` 不把拉开的 `playMarks` 交出去。

`daysPer` 为 0 时才回到旧路径：有 `playMarks` 走 `rulerFromPlay`，否则 `rulerMarks`。空月压缩只在这条旧路径里。`脉络同日间隔` 两种模式都不参与标尺。

一屏天数开启时，`playLayout(..., { lockDay: true })` 不往日历里插空白。同一账户当天多笔平分最多 0.9 天，每笔的进度窗口是 `dur` 像素，而不是把尺子拉长。窗口像素大于一天的像素时，动画被收到当天内。

## 4. 布局 → 脉络 的全部参数

来源：`LV_SCHEMA`（`js/core/lv-settings.js`）。面板分组就是 `LV_GROUPS`。枚举在界面上显示中文选项，存的是选项文字；`readLvParams` 再映射成内部值。范围是 schema 的 `min`/`max`。没有写 min/max 的颜色项只做字符串。

读回时：分档若 CSS 里的数 `> 8` 则除以 100 当成倍率，否则原样当倍率（`asMult`）。所以 100 → 1，遗留的 1 仍是 1。`normalize` 里若键以「脉络倍率」开头且存盘值 `≤ 8`，会 `×100` 再钳制（1 → 100，1.5 → 150）。已经大于 8 的不再乘。第二次打开不会再乘，因为新值已 &gt; 8。七档按这个顺序被抬成非递减：倍率1、10、100、1000、5000、1万、10万。因此「倍率10 = 150 且倍率100 = 100」会被收成 150。这是代码，不是疏忽记录。

## 5. 还没解决的，以及怎么验收

### 代码里仍在、不能说已经修好

- 吸附没有第二条时钟。圆让位的速度就是半径随滚动变化的速度。同一天排得很密时，这段滚动很短，让位看起来会快，但不是换列或瞬移。
- 颈在表面间隙约 1.5px 时出现，第一道能通过轮廓检查的圆弧大约 0.5px。不是隔着空隙突然长出一条粗颈，也不是数学上从 0 宽度连续长出。
- 完成后飞来的金额字和终点上刚跳变的余额字叠在同一圆心，字会淡掉，余额数字本身仍是跳的。
- 窄屏上直径大于所在区域时，圆会伸进隔壁。分类不错，要用最大直径去限。
- `脉络同日间隔`、`脉络相斥` 在面板上能改，画面布局不看它们（2.4、上一节）。
- 新账户在标签跳变前半径可以是 2px 的点，飞泡却按全额画。转账前半段目的地几乎看不见。
- `packCluster` 仍把多颗资产推到表面间隙约等于 `脉络间隙`（默认 4）。飞泡若比这个间隙大，中途要靠外拱的弧才能不压进两端。v1.564 的测量说明靠得很近时曾经整段重叠；v1.565 没有再量「所有金额、所有缩放」下的最小间隙。
- 不同账户允许同一滚动区间里各有一笔在飞。飞泡之间仍有 14 次互相推开，推不开时会挨在一起。没有承诺「不同账户的飞泡也不重叠」。
- 右缘合计的 y 用该分类当天 **最早一笔** 的播放位置（`bagAt`）。后面几笔完成时，这颗合计可能已经滚到画面上方。
- 内光/外晕是沿轮廓的三笔实线，不是连续渐变。默认 0.1 时很淡；把强度拉到接近上限，能看出分层。这不是桥弧错位，但是和「一层柔光」的观感可能有差。 **v1.565 没有在默认 5% 填充下再截一套给用户看过的成片。** 高对比图只能证明线贴着填充，不能代替默认质感的验收。
- 固定收支 / 分期的未来虚拟流水仍不进这张图（旧可行性文已写，代码路径未在本次文档更新里重读证明）。
- 几何测试和 `bubble-align.test.mjs` 不打开手机，也不截 DPR=2 或缩放后的帧。

### 建议的验收（每一条都要看画面，不要只看测试绿）

代表账自己造，不要把真账本贴进仓库：一张储蓄卡、一张零钱、一张信用卡、一笔借款、工资、同一天两笔不同分类的支出、一笔互转、一笔还款、一笔把零钱花到 0。

### 本地怎么对版本（不能用 `?v=` 随机数代替）

版本是 `nt/js/core/version.js` 里的 `APP_VER`，以及 `nt/sw.js` 里的 `CACHE_NAME`。两者必须同为 `nt-v1.566` 才是这一版。

地址栏加 `?v=随机数` **不会** 改这两处，也不是程序版本。Service Worker 按 `CACHE_NAME` 换缓存。只改查询字符串，可能仍跑上一版的脚本。

在自己的检出目录（以前查过的一台机器是 `D:\myproject\money-way`；若不是这个文件夹，就在你实际打开的那个目录里做）：

```powershell
git fetch origin main
git checkout main
git pull origin main
git rev-parse HEAD
# 应看到引入 nt-v1.566 的那次提交（以本文发布后的 main 为准）
Select-String -Path nt\js\core\version.js -Pattern "APP_VER"
Select-String -Path nt\sw.js -Pattern "CACHE_NAME"
node nt/tools/serve.mjs 8080
```

浏览器打开 `http://127.0.0.1:8080/nt/index.html`。校验页看版本是否 `nt-v1.566`。若 PWA 仍旧，用校验页的更新，或关掉站点再开。线上对照：`https://jefely.github.io/money-way/nt/js/core/version.js`。

本文作者 **不能** 改你电脑上的文件夹。拉取之前，本地可以仍停在旧提交。

## 6. 为什么会乱（证据和假设分开）

### 有记录的

1. **要求换过几代，文档没换。** 六泳道、四列、三区先后都写成过「当前」。`BUBBLE-FEASIBILITY.md` 直到这次更新仍写「实现以本文为准」。读旧文会去实现已经取消的轴和「标签按进度加欠款」。
2. **绘制状态是共享的，回归没有被测试抓住。** v1.565 之前 `paintUnion` 在内发光之后直接 `stroke()`。内发光对轮廓的每一段（含桥弧）`beginPath` + 画圆。最后一段是桥弧，白线就描它。填充早前已经按合并路径画过。几何测试只检查弧段在数学上首尾相接，不调用 `stroke`。所以测试可以全绿，而白线和填充分家。v1.564 的拼图里这已经可见，当时的说明把它当成「飞泡和余额正确」而通过了。
3. **v1.564 的选点 bug 是比较写错，不是需求不清。** `best.score` 未赋值，更好的圆边点不会胜出。代表账上的测量（两端同时被直径约 45 的飞泡盖住，对象在 t≈0.42 切换）对应该提交的场景函数，不是两圆演示。
4. **v1.563 把标签和半径拆开，但留下两个面板旋钮不接画面**（同日间隔、相斥）。这是集成没做完，不是用户又改了需求。
5. **v1.563 的缓存名曾先被提交成 v1.562**（`0f2e2c4` 的 `sw.js`），下一提交 `443347b` 才对齐。说明版本号和缓存名要在同一次提交里看一眼，不能假设改过 `APP_VER` 就改过 `CACHE_NAME`。

### 假设（没有单独的实验证明）

- 宽屏「全部挤在中间」在用户本机 v1.561 上的直接原因是 `cameraFit` 包含左右缘。代码路径和后来的测量一致，但没有在用户那台浏览器里复现截图。v1.563 改了镜头之后，代理环境的 1280/1920 图能看到左中右分开；用户是否在自己的缩放下仍觉得挤，本文没有新的用户截图。
