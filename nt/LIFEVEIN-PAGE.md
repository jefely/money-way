## 二、页面长什么样

第一版（已实现）：

```
LIFEVEIN   上下滑动 · 中域（资产 / 负债）
收入 ¥…  ·  支出 ¥…  ·  净 ¥…
[ 更早的 N 条 ]
──────────────────────────────────────────
10-22  ●  招行储7912  −¥4.00  → 地铁     余额 ¥3,570.65
10-22  ●  招行储7912  −¥4.00  → 地铁     余额 ¥3,574.65
10-21  ●  招行储7912  −¥5.00  → 日用品    余额 ¥3,639.65
…
```

- **一条流水一个泡**：泡里是节点名 + 这一笔金额 + 去向；**余额写在泡外**。
- **泡的大小 = 金额**：≥1000 大、≥100 中、其余小（三档，不随数据线性缩放，避免长泡挤坏排版）。
- 时间轴竖着穿过去，圆点落在轴上；进页面先停在**最新**一条，往上滑看更早。
- 首屏 100 条，点「更早的 N 条」再加 100 条，视口不跳。

第二版才做（设计稿里的三域与折叠）：

| 域 | 放什么 |
|---|---|
| 左 | B 极源头：收入 / 权益 |
| 中 | A 极中转：资产 / 负债（第一版只做了这一域） |
| 右 | A 极终点：成本 / 费用 |

**折叠**：A→B 之后 B 立刻转给 C，中间 B 合成一个泡、连线从 A 穿到 C；沉淀几天再出发用竖虚线表示时间跨度。
往上滑出屏幕边缘的旧泡渐隐缩小。

## 三、口径（已写进 core，别再改）

| # | 规则 | 落在哪 |
|---|---|---|
| 1 | 一笔流水**至少一端是中域**（资产 / 负债）才出泡；两端都不是就不出 | `isMiddleType` |
| 2 | 方向：中域是转出方 = `out`，是转入方 = `in`，**两端都中域 = `transfer`**（转账、还款） | `buildLifeVein` |
| 3 | 余额 = **这笔之后**该节点的余额；借贷方向按 `isDebitType`（负债转出 = 欠款增加） | `deltaOf` |
| 4 | 转账 / 还款的泡记在**转出方**；另一端的余额放在 `otherBalance` | `buildLifeVein` |
| 5 | 合计按**净额**：收入类转出算收入、转入算退回；费用类转入算支出、转出算退回 | `totals` |
| 6 | 草稿（`status:'draft'`）不出泡、不进余额、不进合计 | `isPosted` |
| 7 | **缺端照出泡**（项目裁决：绝不自动跳过），另一端名字留空 | `otherName` |
| 8 | 期初照出泡，但标「期初」 | `isOpening` |
| 9 | 排序：日期升序，同一天按 `seq`（与流水表一致） | `byDateSeq` |

> 第 6 条与统计页口径一致；第 7 条是 v1.469 的裁决（「认不出就跳过」被明确否掉）。

## 四、数据从哪来（不新增会计口径）

```
state.transactions（已入账流水，按 date + seq 排）
state.accounts（节点名、类型）
        ↓  纯函数
core/lifevein-model.js   →  rows / totals / span
        ↓
views/lifevein.js        →  DOM 气泡 + 竖轴 + 分批
css/lifevein.css
```

- 余额**不另算一套**：与 `core/balance-calculator.js` 同一条 `isDebitType` 规则。
- `core/` 不碰浏览器 API（门禁强制）。
- 没有「本期」时间范围：第一版合计 = **全部已入账**。要做月/年，等第二版接 `timeline/time-state.js`。

## 五、第一版落地的实测（2026-11-08，真账本）

| 项 | 结果 |
|---|---|
| 数据 | 真账本备份 `.lz`（86 节点 / 1000+ 流水） |
| 气泡 | **402 个**（中域口径） |
| 合计 | 收入 ¥12,063.94 · 支出 ¥6,401.66 · 净 ¥5,662.28 |
| 首屏 | 100 条 + 「更早的 302 条」，滚到底（最新） |
| 390px | 无横向溢出（`scrollWidth − innerWidth = 0`） |
| 测试 | 10 条（方向 / 余额 / 负债 / 合计 / 草稿 / 缺端 / 期初 / 排序 / 空账本） |

**顺带暴露的数据问题**：`交行储8380` 的余额一路是负数（−¥282 → −¥546）。
按口径它被当成资产类算的；要么它其实是信用卡（该改成负债类），要么有一笔转账方向录反了。
这页的价值之一就是这个 —— 余额负数一眼能看见。**没改账本**，等用户裁决。

## 六、明确不做（第一版）

- 三域泳道、折叠穿透、视差、弹簧回弹、震动、音效 —— 全不做；
- EHT-NV（第十六部分，生命资产）**不在这个页面**；
- 不做第二套余额算法；
- 不做横向手势（第一版就是一列）。

## 七、第二版的入口
