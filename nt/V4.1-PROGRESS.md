## 一、结论

**17 个部分里，前 7 部分落地，后 10 部分一行代码都没有。**

分界线很整齐，正好落在设计稿自己写的「第七部分 架构底线与落地顺序」：

| 段落 | 内容性质 | 状态 |
|---|---|---|
| 第一部分 – 第七部分 | 账本内核 + 环图（**已有产品的地基**） | ✅ 基本落地 |
| 第八部分 – 第十七部分 | 新增推演引擎（沙盘 / 摊销 / 归因 / 减值 / 盘点 / 指令 / 多币种 / 模板 / EHT-NV / Money Vein） | ❌ 全未实现 |

设计稿在第七部分末尾写的首要任务是「放弃写 UI 和图表，立刻去写 `core/event-engine.js` 和 `core/calc-engine.js`」——
**这条已经做完了**（两个文件 + 17 条测试：`event-engine.test.mjs` 10 条 / `calc-engine.test.mjs` 7 条）。
但它的下一句「再谈替换」还停在原地：
新内核目前是座孤岛，产品仍在跑旧模型。§三 展开。

### 第四部分 三层套娃视觉引擎 — 🔁 实现后主动简化

所以 `EVENT-MODEL.md` §7.3 写的「三层嵌套环未做」是**过时说法**，

## 三、最要紧的一条：桥搭好了，车还没开上去

**`core/event-engine.js` + `core/calc-engine.js` 至今仍没有产品代码调用。**
除彼此、自身测试、`sw.js` 缓存清单、以及注释里的引用之外，`ui/`、`views/`、`graph/`、`app.js`
一处都没 import 它们。实际跑的东西仍然是：

| 层 | 现在吃的数据 |
|---|---|
| 环图 | `transactions` + `accounts`（`graph/mw-data-fetcher.js` 只认 `from_id` / `to_id`） |
| 导入 / 导出 | `transactions`（`core/xlsx-write.js` / `xlsx-read.js` / `lz-file.js`） |
| 同步 | `transactions` |
| 校验页 | `core/validate.js` 的旧 V1–V7，不是 `auditBook()` |

这是**刻意的**（`EVENT-MODEL.md` §8 写过理由：新内核先证明自己算得对，再谈替换）。
2026-11-07 补上了此前一直缺的 `core/ledger-adapter.js`（`transactions` → `events` 单向投影），
它同样没接进界面 —— 只被测试和 `tools/audit-book.mjs` 使用。

它带来三个具体的、用户能感觉到的后果，现在**都有了解法、但都还没落地**：

1. **成本类看不出和资产类有任何区别。** 类型下拉里有「成本类」（读 `ALL_ACCOUNT_TYPES`），
   极性也对，`physicalBook()` 也算得出原值/残值/已处置——
   但 `ui/` 目录下 **`originalCost` / `itemStatus` / `residual` 零命中**，账户表没有这两列。
   用户选了成本类，界面上得不到任何反馈。
   *适配器已把 `originalCost` / `itemStatus` 投影进节点，`physicalBook()` 能直接算残值；
   缺的只是账户表两列。*
2. **合并节点没有入口。** `mergeNode()` 写得很完整，但没有界面能触发它。
   *适配器投影后 `resolveNodeId()` 已能把旧 ID 的连线重定向算通，缺的仍是入口。*
3. **拆分流水没有入口。** `splitEvent()` 同上。

所以缺件从「一个」变成「两件事」：

- ① **拿真实账本验证适配器** —— 账本在浏览器加密库里，agent 取不到；
  用户「导出文本」后跑 `node nt/tools/audit-book.mjs 账本.txt`。
- ② **把适配器接进产品**（校验页先显示「新引擎重算 vs 旧算法」的对账结果，
  再谈账户表两列与合并/拆分入口）。

## 五、唯一卡住的裁决

**线宽到底表示什么。**（`EVENT-MODEL.md` §7.1）

| | v4.1 §4.3 | 现行 `MONEYWAY-SPEC.md` §3.1 |
|---|---|---|
| 线宽 | 发生金额（比例缩放） | 转入账户类型的权重（费用 4× / 资产 3× / 负债 2× / 权益收入 1×） |

现行实现是 `strokeWidth = unitArcLen × 0.8 × WEIGHT_MAP[targetType]`，
**金额信息完全不进线宽**。两者不可共存。

而且现在越来越别扭：弧段的**宽度**已经能按金额切了（第二套粒度模式），
弧段的**线宽**却还按类型查表——同一根线，两个语义。

这条不定，三层环画出来还是错的，所以它卡着视觉层的一切后续。
**改它要动 `mw-path-calculator.js` 整套线宽表 + 重定「同目标多线叠压」——需要拍板后再动。**
