# Money Way · 环网图设计规范

> 本文件是 `nt/` 多文件版**路径追踪图**的唯一设计依据。
> 代码对应：`graph/mw-data-fetcher.js` → `graph/mw-slot-calculator.js` → `graph/mw-path-calculator.js` → `ui/mw-svg-renderer.js`
> 术语（**账户类型 vs 统计分类**）见 [`GLOSSARY.md`](GLOSSARY.md)。

---

## 一、三大功能

### 功能一：费用类构成的直观追踪（反向溯源）

- **场景**：这个月「吃饭」花了几千块，是刷了招行、用了微信，还是透支了花呗？
- **算法**：以选中的费用类账户为起点，**反向 BFS**（沿指向它的边逆流而上），一直追到资产/负债/收入。
- **输出**：一个包含所有链路节点与边的集合（`path-tracer.js` 的 `traceUpstream`）。
- **渲染**：点击「吃饭」弧块 → 无关线透明度降到 `0.02`，相关线按离费用端的层级加粗。

### 功能二：资产类与负债类的循环交互（资金腾挪）

- **场景**：用招行还中信、用微信还花呗，钱在资产与负债之间高频空转。
- **算法**：提取「资产↔资产 / 负债↔资产 / 资产↔负债」的边（`extractLeverageLinks`）；
  DFS 时必须用 visited 切断死循环（`hasCycle` 可检测「倒卡」环）。
- **渲染**：这部分线最密，默认调细；顶部给一个 Filter：「显示/隐藏内部转账」。

### 功能三：全链路流向（上帝视角）

- **场景**：这个月的「水源（收入/负债）」，经过什么「管道（资产）」，灌溉了哪些「农田（费用）」。
- **算法**：`mw-slot-calculator.js` 按类型排序分配槽位；环上每段长度 = 该账户参与的**流水笔数**（不是金额）。
- **渲染**：全局连线不隐藏，让资金交织的复杂度成为信息本身。

## 二、圆环布局规则

### 2.1 颜色与分组的区别（**最容易搞错的一条**）

| | 依据 | 结果 |
|---|---|---|
| **颜色** | **统计分类**（储蓄 / 信用 / 日常 / 餐饮 …） | **颜色数 = 统计分类数**，与账户类型无关 |
| **聚合与分界** | **账户类型**（资产类 / 负债类 / 费用类 …） | 同一类型的账户聚在一起，**类型之间画分界线** |

> 同一个统计分类的账户**都用同一个颜色**；
> 同一**账户类型**的账户**聚合在一起，并显示界线**；
> 不同**账户类型**的账户之间**间隔 0.8° 的弧长**。

代码里对应两个键，**永远不要合并**：

```js
sortKey  = 类型 | 统计分类     // 决定顺序与缝隙
colorKey = 统计分类            // 决定颜色
```

### 2.2 细粒度：两套模式（2026-11 用户定）

同一张图有两种「弧段怎么分」的口径，面板「粒度模式」切换（0 / 1）。
两套的**分组、颜色、缝隙完全一样**，只有弧长变 —— 切过去不会像换了一本账。

#### 模式 0 · 笔数（默认）：钱动了多少次

```
单位数 N_UNITS  = 流水笔数 × 2        （每笔在转出端、转入端各占一个）
单位角 unitDeg  = (360 − 分组数 × 0.8) ÷ N_UNITS
```

`分组数` 是 `类型|分类` 的组合数（代码里是 `groupList.length`，不是类型数也不是分类数）。
**用户给的验收例子**：1000 笔 + 20 个分类 → `(360 − 20×0.8) ÷ (1000×2) = 0.172°/单位`

#### 模式 1 · 金额：余额变动了多少

**六大节点类型之间均分**（只分**出现过的**类型），类型内按**净额**占比（用户 2026-11 定）：

```
出现的类型数 N = 当前筛选结果里真正有账户的类型个数（1~6）
可用角 avail     = 360 − N × 0.8
类型角           = avail ÷ N          ← 均分，与金额无关
                    出现一类 → 占整圈；两类 → 各一半；三类 → 各三分之一
净额             = 转入 − 转出        （余额变动，不是收付合计）
节点角           = 类型角 × (|节点净额| ÷ 该类型内 |净额| 之和)
槽位角           = 节点角 ÷ 该节点的槽位数
```

**「统计分类」这一层不参与角度分配**：它只管颜色与排序。
类型内部跨分类**不再留缝**（缝只留在类型之间），所以整圈永远是满的；
四种模式的分组、颜色完全一致，只有弧长变。

**净额口径的代价，必须知道**：中转账户（本月转入多少就转出多少）净额为 0，
弧段宽度就是 0，**它会在环上消失**；整个类型净额都是 0 时那一段直接留空。
想看「钱经过了多少」请用模式 0 —— 两种模式回答的是两个不同的问题。
全部净额为 0 时自动退回模式 0。

> ⚠️ **内部一律用弧度**。`unit` 是弧度，`spansByAmount` 的返回值也必须是弧度。
> 2026-11 这里返回过「度」而被直接加进弧度累加器，一个块跨到 9731°（27 圈），
> SVG 的 `A` 命令碰到超 360° 的弧会**悄悄把半径放大** ——
> 图上就是几个飘在环外的大圆环（用户原话「感觉怪怪的」）。
> 判据：单个槽位的 `span` 必须 `< 2π`，整圈合计不超 `2π`，测试里已钉死。

环的渲染尺寸可随细粒度级别调整（单位多时放大画布，保证单个单位仍可点）。

### 2.3 排序

从 9 点钟顺时针，按账户类型：

```
收入类 → 资产类 → 费用类 → 负债类 → 权益类 → 其它
```

「上面收入，下面权益」——符合直觉。类型内部再按统计分类、账户名、时间排。

## 三、线宽与颜色（v4.0 修正版，2026-11）

### 3.1 线宽：只有追踪模式是新设计（2026-11 定稿）

| 模式 | 命中线 | 非命中线 |
|---|---|---|
| **基本** | 单位弧长 × `默认线宽比例`（**20%**），全图统一 | — |
| **单线** | 单位弧长 × `命中线宽比例`（**32%**） | 20%，被遮罩盖住 |
| **色块** | 单位弧长 × `命中线宽比例`（**32%**） | 20% |
| **追踪** | **漏斗**：宽头 `4 + 金额占比 × 4`，细头 `1.2`，前 `变细起点比例`（50%）等宽 | `traceFloor` = **1.2** |

用户原话：「除了追踪模式，统一线宽设置。默认线宽一个值，命中一个值」，
**2026-11-03 定稿为 20% / 32%**。

除追踪外只有两档，都相对 `unitArcLen`；下限 0.4、上限 14（画布单位）。
**笔数很少时两档都会撞上限**，那时看不出 20 与 32 的差别。

另外 `默认线宽`（2.4）是**整体倍率**：最终线宽再乘 `默认线宽 / 2.4`，
所以它调到 4.8 就是全部粗一倍。

追踪模式的五项参数（漏斗宽头 / 漏斗细头 / 变细起点比例 / 追踪深度 / 追踪非命中线宽）
在面板里单独成组「环图·追踪」，不再混在「线」和「规则」里。

### 3.4b 追踪模式的两组文字（2026-11-03 定稿）

追踪模式下，**每条命中线在转入端**贴两组白色文字，以内弧线为基准左右分开：

| | 位置 | 内容 | anchor |
|---|---|---|---|
| **序号** | 内弧线**内方**（圆里侧，`rIn − 环厚×13%`） | 这一笔在资金路径上的层号：`0` / `-1` / `2` … | `end`（从弧线往里长） |
| **金额** | 内弧线**外方**（环上，`rIn + 环厚×12%`） | 该笔发生金额，**不带 ¥** | `start`（从弧线往外长） |

- 朝向与环外的账户标签一致：**沿半径向外辐射**，下半圈自动翻 180° 免得倒着读。
- 序号字号 46、金额 58（画布单位），白色 + 黑色描边（`paint-order: stroke`）。
- 两者都 `pointer-events: none`，不抢点击、不挡拖动。

**序号的来历**见 §5.2：`0` 是选中的那笔，正数是钱往下游走，负数是往上游追。

同一往返账户的多笔会贴出多组数字（角度按槽位分开）；若密集到叠字，
下一步该做的是「同账户合并显示合计」，而不是把字再缩小。

> 被这套取代的历史方案（代码都还在，但没人读）：
> `WEIGHT_MAP`（按转入类型 4×/3×/2×/1×）、`DEPTH_WIDTHS`（按离费用端几跳）、
> `FIXED_WIDTH`（按转出类型 6/4/2.4/1.2）、`BLOCK_WIDTH`（按弧块类型 6/4.8/3.6/2.4/1.2）。
> 面板里 `基本模式线宽倍数` / `命中加权` / `命中收缩` / `命中额外系数` 四项也因此不再影响线宽
> （`默认线宽` 2026-11 已恢复作用：它是**整体倍率**，2.4 = 1 倍）。

### 3.2 颜色**永远**等于转出节点的专属色

一笔钱从谁那里出去，线就是谁的颜色 —— 与转入方、与统计分类都无关。
这就是 v4.0 的「温度计红泡原理」：点某个节点时，**同色线 = 流出，异色线 = 流入**。

`STYLE_UP` / `STYLE_DOWN` 里的 `colorBy` 因此失效。

### 3.3 线型

实线 = 已发生；虚线 = 未来预演（虚拟流水，`isVirtual`）。

### 3.4 变宽线（漏斗）—— 只在路径追踪的命中线上

```
宽头 = 漏斗宽头（4） + 金额占比 × 漏斗宽头      ← 贴在**转出**端
细头 = 漏斗细头（1.2）                          ← 贴在**转入**端
金额占比   = 该笔金额 ÷ 当前图里最大的一笔（0~1）
变细起点比例 = 0.5                              ← 前 50% 等宽，后 50% 一路收到细头
```

三个参数都在面板「环图·追踪」里，改的是绝对值（基准单位），不是倍数。
`变细起点比例` 调 1 = 全程等宽不收尖，调 0.2 = 从两成处就开始收。

**其余模式一律等宽**：一圈几百条线全做成漏斗只会更花，
漏斗的价值是「这一条链往哪走」，那是追踪模式才有的语义。
追踪模式下非命中线压到 `traceFloor` 等宽。

SVG 的 `stroke-width` 是恒定宽度，画不出漏斗，所以用**闭合 path**：
两侧各沿「该端切线的法线」偏移半个线宽，再各用一段三次贝塞尔连起来。
几何全在 `graph/mw-chord-shape.js`，渲染器只拼点。

### 3.5 两层环（2026-11 定稿）

```text
外圈（细线，环厚的 10%）  六大类型的固定色
内圈（环厚的 90%）        每个节点一个专属色
```

**中圈（统计分类）已取消**：分类在角度上本来就有 0.8° 的缝，
再画一圈同色系的分类带，等于把同一条边界说两遍，还多出一整圈颜色。
分类的信息由「缝隙 + 排序」表达，不需要再占一层。

| 层 | 是什么 | 厚度 | 颜色 |
|---|---|---|---|
| **外圈** | 六大类型 | 10%（看上去就是贴着环的一条线） | 固定色系：费用红 / 资产蓝 / 收入绿 / 负债橙 / 权益紫 / 成本灰 |
| **内圈** | 节点弧块 | 90% | 每节点专属色（`nodeColor(i)`，24 色 maximin + 黄金角兜底） |

两层**共用同一套角度**：外圈是内圈按 `type` 的聚合视图，边界天然对齐。
`环厚` 默认值为此从 44 提到 **64**（10% 才够画成一条看得见的线）。

> **内圈按「类型内节点总数」均匀分布色相**（2026-11 第三次修正）：
>
> ```
> 第 i 个（该类型共 n 个）= 色相 offset + i × 360/n，明度 44/62/36 轮转
> ```
>
> 试过三版：
> ① 按全局序号取 maximin 调色板 —— 同类型相邻拿「浅蓝 / 蓝」，缠成一团；
> ② 黄金角 137.5° —— 相邻差了 137°，但**隔 5 个就绕回来**（i=1 是 137°、i=6 是 105°），
> 资产类有 7 个账户就出现「两个绿」，而资产类内部本来就有互转，两团绿线会交叉；
> ③ **均匀分布** —— n 个点铺满色相环，任意两点的最小间隔就是 `360/n`，
> 这是「n 个颜色两两尽量远」的最优解，不会像黄金角那样隔几个绕回来。
>
> 注意这与「分类不用黄金角」不矛盾：分类固定十来个、要么全远要么撞；
> 节点的数量已知且可以按 n 现算，均匀分布严格优于任何固定步长。
>
> `buildArcs` 仍会返回 `cats`（分类聚合），`categoryTint` 也还在 ——
> 那是留给「以后想把分类圈加回来」的，界面当前不用。

## 四、引线与端点

- **连线端点**：从 **R_connect**（内层环的**内沿**，`r0`）射出，取该单位弧长的**中点**（`slot.mid`）。
  这是 v4.0 §4.3 的原话 —— 连线只碰最内层，不穿外两层。
- **弧块**：相邻同账户的槽位合并成块，占 `[a1, a2]`；三层用同一个 `[a1, a2]`。
- **文字**：沿半径向外辐射；放不下时用锥形引线推到环外（见旧版 `PATH-CHART.md`）。

## 五、连线聚焦模式

| 状态 | 线宽 | 透明度 |
|---|---|---|
| 全局（什么都没选） | 统一基准 | `0.20` |
| 命中（点中的那一条） | 权重 × 1.35 | `0.95` |
| 相关（同一链路） | 权重 × 0.8 | `0.55` |
| 无关 | 权重 × 0.45 | `0.02` |

移动端：手指按住弧块即进入聚焦，抬起恢复。

### 5.1 点弧块看哪一侧：由**节点类型**决定（2026-11 取代方向开关）
原来的「逆流 / 顺流」按钮**已取消**。现在点弧块看哪一侧，写死在
`graph/path-tracer.js` 的 `ACC_SIDE` / `sideForType(type)` 里：

| 点中的类型 | 看哪一侧 | 为什么 |
|---|---|---|
| **收入类 / 权益类** | 只看**转出** | 它是源头，钱从这来，只关心往哪去 |
| **资产类 / 负债类 / 成本类** | 转入 + 转出**都看** | 中转站，两头都是它的故事 |
| **费用类** | 只看**转入** | 它是终点，钱花到这，只关心从哪来 |

线色仍然**永远**取转出节点的专属色。所以点费用类时，看到的全是别人（转出方）的颜色；
点收入类时，看到的全是它自己的颜色 —— 这正是「同色 = 流出、异色 = 流入」的语义。

**点弧块与点左栏是两条不同的路**：

- 点弧块 → `traceByAccount(txs, id, side)`，**只取直接相连的一侧，不递归**。
- 点左栏某一笔 → `traceFlowPath(txs, i, {maxDepth})`，**资金路径**（见 §5.2）。

### 5.2 追踪链 = 资金路径 · **两轮**（2026-11-03 定稿）

选中第 E0 笔（`from0 → to0`）。**向后**分两轮，**向前**只有一轮。

#### 第一轮：链（每层只找一条）

```
E-1 = to0 作为「转入节点」的、在 E0 之前的**最近**一条
E-2 = E-1 的「转出节点」作为转入的、在 E-1 之前的**最近**一条
E-3 = E-2 的「转出节点」作为转入的、在 E-2 之前的最近一条
……
```

关键字是**最近一条**（下标最大），不是最早。取最早会让整条链偏到另一条分支上去。

#### 第二轮：同层补齐 + **金额累计判定**

```
每一层，把「转入账户 == 该层代表记录的转入账户」的其它记录也标成同一层
范围只到该层代表记录之前，不会把未来的记录拉进来

累计：**代表记录本身不占额度**（它是这层的锚，一定收）
     往前每补一笔 → 累计 += 它的金额
     累计 > 选中那笔的发生额 → 停止补**这一层**
```

三条容易写错的（2026-11-03 用户报「-2 累计的不够」就是前两条）：

1. **代表记录不能算进累计**。把它算进去时，补任何一笔都会立刻超
   （`own + amt > own`），同层永远补不进第二条。
2. **停止只作用于当前层**。`-1` 到上限不该把 `-2`、`-3` 一起掐掉 ——
   每层是独立的，超了只说明这一层到此为止。
3. **累计等于上限仍然收**（用 `>` 不是 `>=`）；选中那笔金额为 0 时不判定。

金额上限的道理：同一个账户的流入总额超过它流出的那一笔，说明已经追到
**另一个资金池**了（钱混在一起了），再往前补只会把不相干的流水拉进来。

#### 向前：也是两轮（2026-11-03 加第二层）

```
第一轮（链）
  1 = to0 在 E0 之后第一次作为「转出节点」的那笔
  2 = 它之后第一次作为转出节点的那笔 ……

第二轮（叠加 + 金额上限）
  每层把「转出账户 == 该层代表记录的转出账户」的其它记录也标成同一层
  累计转出额一旦 > 选中那笔的发生额 → 停止叠加（也不再算后续层）
```

用户原话：「1 2 3 4 不用，因为这是汇聚追踪」——那是**第一轮**的语境；
第二层同样要，但**受金额上限约束**：下游各笔加起来超过这笔钱本身，
说明混进了别的资金。

#### 共同的边界

- 「之前 / 之后」按 `data.txs` 的下标（录入顺序 = 发生顺序）。
- 成环靠 `steps` 里已出现过的下标切断，不会 A→B→A 死循环。
- 单侧最大层数 = 面板「追踪深度」：**默认 60，填 0 = 不限**。
- **同名不同 ID 的账户算同一个节点**（`sameAccount` 谓词）：账本合并 / 迁移
  会留下名字一样但 ID 不同的账户，严格按 ID 匹配会让链在那里断掉。
  名称为空或 `—`（断链账户）不参与匹配。

序号的呈现见 §3.4b：`0` 是选中的那笔，正数往下游、负数往上游。

链条为空时**不压暗整张图**，只在页脚说明 ——
一进页面全图变暗会被误读成「图坏了」。

> `STYLE_UP` / `STYLE_DOWN` / `traceWidthOf` 还留在代码里，但 `path-view` 不再调用；
> 方向开关的 DOM 按钮（`#pw-dir`）也已从 `index.html` 删除。

## 六、分层职责（硬性）

| 层 | 文件 | 只做什么 | 绝不做 |
|---|---|---|---|
| 切片 | `mw-data-fetcher.js` | 过滤区间、剔期初、Top N 折叠、1.5% 阈值 | 不算角度 |
| 槽位 | `mw-slot-calculator.js` | 算 `a1/a2/mid`、单位角、弧块、扇区 | 不碰 SVG |
| 路径 | `mw-path-calculator.js` | 算线宽、颜色、贝塞尔控制点、透明度 | 不拼字符串 |
| 渲染 | `mw-svg-renderer.js` | 只把上面算好的数据拼成 `<svg>` | **不许出现三角函数**（门禁强制） |

`pointAt()` 是整个项目**唯一**允许出现 `Math.sin/cos` 的地方，它在第三层。

## 七、两个视觉优化（待做）

1. **线宽渐变**：一根线从资产（3×）流向费用（4×），交界处会突变。
   做法：拆成两段 + `linearGradient`，或按深度分段插值。
2. **同目标多线叠压**：10 条线都流向「地铁」且同色，会糊成一块。
   做法：同起终点同色的线合并成一条更粗的线，或降低单线透明度后叠加。

两者都需要真实数据密度才能定参，先留接口。
