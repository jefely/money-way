# Money Way · 环网图设计规范

> 本文件是 `nt/` 多文件版**路径追踪图**的唯一设计依据。
> 代码对应：`graph/mw-data-fetcher.js` → `graph/mw-slot-calculator.js` → `graph/mw-path-calculator.js` → `ui/mw-svg-renderer.js`
> 术语（**账户类型 vs 统计分类**）见 [`GLOSSARY.md`](GLOSSARY.md)。

---

## 一、三大功能

### 功能一：费用类构成的直观追踪（反向溯源）

- **场景**：这个月「吃饭」花了几千块，是刷了招行、用了微信，还是透支了花呗？
- **算法**：以选中的费用类账户为起点，**反向 BFS**（沿指向它的边逆流而上），一直追到资产/负债/收入。
- **输出**：一个包含所有链路节点与边的集合（`path-tracer.js` 的 `traceUpstream`）。
- **渲染**：点击「吃饭」弧块 → 无关线透明度降到 `0.02`，相关线按离费用端的层级加粗。

### 功能二：资产类与负债类的循环交互（资金腾挪）

- **场景**：用招行还中信、用微信还花呗，钱在资产与负债之间高频空转。
- **算法**：提取「资产↔资产 / 负债↔资产 / 资产↔负债」的边（`extractLeverageLinks`）；
  DFS 时必须用 visited 切断死循环（`hasCycle` 可检测「倒卡」环）。
- **渲染**：这部分线最密，默认调细；顶部给一个 Filter：「显示/隐藏内部转账」。

### 功能三：全链路流向（上帝视角）

- **场景**：这个月的「水源（收入/负债）」，经过什么「管道（资产）」，灌溉了哪些「农田（费用）」。
- **算法**：`mw-slot-calculator.js` 按类型排序分配槽位；环上每段长度 = 该账户参与的**流水笔数**（不是金额）。
- **渲染**：全局连线不隐藏，让资金交织的复杂度成为信息本身。

## 二、圆环布局规则

### 2.1 颜色与分组的区别（**最容易搞错的一条**）

| | 依据 | 结果 |
|---|---|---|
| **颜色** | **统计分类**（储蓄 / 信用 / 日常 / 餐饮 …） | **颜色数 = 统计分类数**，与账户类型无关 |
| **聚合与分界** | **账户类型**（资产类 / 负债类 / 费用类 …） | 同一类型的账户聚在一起，**类型之间画分界线** |

> 同一个统计分类的账户**都用同一个颜色**；
> 同一**账户类型**的账户**聚合在一起，并显示界线**；
> 不同**账户类型**的账户之间**间隔 0.8° 的弧长**。

代码里对应两个键，**永远不要合并**：

```js
sortKey  = 类型 | 统计分类     // 决定顺序与缝隙
colorKey = 统计分类            // 决定颜色
```

### 2.2 细粒度单位

```
单位数 N_UNITS  = 流水笔数 × 2        （每笔在转出端、转入端各占一个）
单位角 unitDeg  = (360 − 类型数 × 0.8) ÷ N_UNITS
```

**用户给的验收例子**：1000 笔 + 20 个分类 → `(360 − 20×0.8) ÷ (1000×2) = 0.172°/单位`

环的渲染尺寸可随细粒度级别调整（单位多时放大画布，保证单个单位仍可点）。

### 2.3 排序

从 9 点钟顺时针，按账户类型：

```
收入类 → 资产类 → 费用类 → 负债类 → 权益类 → 其它
```

「上面收入，下面权益」——符合直觉。类型内部再按统计分类、账户名、时间排。

## 三、线粗与颜色（核心规则）

### 3.1 线粗：由**转入账户的类型**决定

| 转入类型 | 权重 | 含义 |
|---|---|---|
| 费用类 | **4×** | 终点，钱真正花掉的地方，最粗 |
| 资产类 | **3×** | 中转站，资金主动脉 |
| 负债类 | **2×** | 杠杆，额外补充 |
| 权益类 / 收入类 | **1×** | 期初/源头，背景板 |

### 3.2 线粗基准

```
1 倍线粗 = 1 个细粒度单位对应的弧长 × 80%
strokeWidth = unitArcLen × 0.8 × weight
```

### 3.3 颜色：由**转入账户的统计分类**决定

一笔钱 `工资 → 招行储 → 餐饮`，画在「招行储→餐饮」这段的线，
取**转入方「餐饮」的统计分类**的颜色。于是所有流向餐饮的线汇成一束同色。

用黄金角（137.508°）分配色相，保证相邻分类差异最大、同分类永远同色。

## 四、引线与端点

- **连线端点**：落在**圆环内弧**上，取该单位弧长的**中点**（`slot.mid`）。
- **弧块**：相邻同账户的槽位合并成块，占 `[a1, a2]`。
- **文字**：沿半径向外辐射；放不下时用锥形引线推到环外（见旧版 `PATH-CHART.md`）。

---

## 五、连线聚焦模式

| 状态 | 线宽 | 透明度 |
|---|---|---|
| 全局（什么都没选） | 统一基准 | `0.20` |
| 命中（点中的那一条） | 权重 × 1.35 | `0.95` |
| 相关（同一链路） | 权重 × 0.8 | `0.55` |
| 无关 | 权重 × 0.45 | `0.02` |

移动端：手指按住弧块即进入聚焦，抬起恢复。

## 六、分层职责（硬性）

| 层 | 文件 | 只做什么 | 绝不做 |
|---|---|---|---|
| 切片 | `mw-data-fetcher.js` | 过滤区间、剔期初、Top N 折叠、1.5% 阈值 | 不算角度 |
| 槽位 | `mw-slot-calculator.js` | 算 `a1/a2/mid`、单位角、弧块、扇区 | 不碰 SVG |
| 路径 | `mw-path-calculator.js` | 算线宽、颜色、贝塞尔控制点、透明度 | 不拼字符串 |
| 渲染 | `mw-svg-renderer.js` | 只把上面算好的数据拼成 `<svg>` | **不许出现三角函数**（门禁强制） |

`pointAt()` 是整个项目**唯一**允许出现 `Math.sin/cos` 的地方，它在第三层。

## 七、两个视觉优化（待做）

1. **线宽渐变**：一根线从资产（3×）流向费用（4×），交界处会突变。
   做法：拆成两段 + `linearGradient`，或按深度分段插值。
2. **同目标多线叠压**：10 条线都流向「地铁」且同色，会糊成一块。
   做法：同起终点同色的线合并成一条更粗的线，或降低单线透明度后叠加。

两者都需要真实数据密度才能定参，先留接口。
