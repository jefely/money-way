## 1. 流水（Flow）✅

**列标**：`序 | 日期 | 转出节点 | 转入节点 | 金额 | 备注`　**冻结**：序

### 1.1 单元格编辑（2026-11-09 · 照 Excel）

- **单击**：只选中这一格（1px 主色内描边），**不进编辑、不显示光标、不画文字选中框**，
  但键盘照常弹出 —— 键盘焦点由**屏幕外的 1px 隐藏 input**持有（不复制旧值、不 select，
  安卓不会在左上角画全选框），可见输入框从不 focus。
  格子右下角出现**调整大小手柄**；拖它把选区扩成矩形（手机 / 鼠标都行），
  手柄的触摸命中区 56×56（还向格外多伸 10px），可见的仍是右下角 10px。
- **多格 / 整行选区**：一个样式，日期不再单独描边；四边由选区最外圈格子的
  **1px 描边**拼成（和单格一样粗），内部格线透明、整块连续底色。
  框随格子一起滚动：不会跑到序冻结列上面，切到负一屏节点设置页也不会留在那，
  左右滚动时不晃。
- **拖出多格松手**：自动弹出 `剪切 / 复制 / 粘贴 / 清除 / 编辑` 菜单；
  **单个格子不自动弹**，仍靠长按（480ms）。
- **点行号（序）**：选中该行「日期..备注」并直接弹菜单；点其它格子取消行选、
  变成选中被点的格子（键盘照常弹出）。
- **开放录入区（空行）**：内容按「第几个空行」存进 `state.openRows`，不建流水、
  不移动；重新进入仍在原位。**金额一有值就补今天日期 + 预分配序号**（序号显示在序号列），
  失焦时金额格式化成金额；但仍留在原位；只有切回流水记录表时才结算成正式流水
  （沿用这个编号、落到尾行）。没金额的行永远不编号、不移动。
- **直接打字**：整格替换（隐藏格 focus 时全选，第一次输入即替换）；回车填入。
  **不会因此进入编辑态**。
- **再单击**：取消选中（键盘收起）。两次点击落在双击窗口内算双击，不算「再点」。
- **双击**：才进入**编辑**：焦点交回可见输入框，光标落在点下去的位置、光标显形，
  可精确增删；此时输入框才恢复 pointer-events，长按交给系统选字。
- **长按 480ms**：在该单元格**上方**弹出唯一一条菜单：
  `剪切 / 复制 / 粘贴 / 清除 / 编辑`。点菜单外面收起；点表格外同时取消选区。
- **Enter / 键盘「下一个」**：同一行**往右**一格（日期 → 转出 → 转入 → 金额 → 备注）；
  到备注后跳到**下一行的转出节点**（不是下一行的日期）。
  **Tab / Shift+Tab**：DOM 顺序里的下一 / 上一可编辑格（跳过只读行）。
- **换格 / 取消选中前**会先收尾上一格：简码解析成节点名、金额格式化、空行建单。
- **Esc**：编辑态 → 还原本次改动、退回选中态；选中态 → 取消选中。
- **方向键**：选中态移动格子；编辑态交给浏览器移光标。
- 行 hover 只在 `hover: hover and pointer: fine`（真鼠标）生效 ——
  手机上点一下不再整行染色（「看起来像整行被选中」的根因就是这条 sticky hover）。

- 工具栏：添加（批量文本）/ 同步（二维码）/ 导入 / 导出
- **同步弹窗（v1.90）**：自适应天数 ——
  右侧竖轮选截止日（年份在竖轮上方、右缘与竖轮对齐）；从这天往前**按天**装流水，
  一张码装满为止（`core/sync-window.js` 二分找最大窗口；装不下的那天整天不要）；
  二维码固定 220×220 靠左，下方写明「包含 9/5 — 9/9 · N 笔」，紧跟「保存二维码图片」；
  点二维码用第二个 `<dialog>` 全屏放大；没有流水时同尺寸虚线占位，有码无码布局都不动；
  ② 一个文本框打通复制与接收：复制 / 清空 / 粘贴 / 同步（同步＝合并框里的内容）
- 日期：输入 `YYMMDD`，输入 `:` 自动补当天
- 转出/转入：输入简码，失焦自动解析成真名并绑定 `id`；≥2 字符弹候选气泡
- 金额：数字键盘，保留两位小数
- 行尾 `×`：删除并重算余额
- 底部：`共 N 笔 · 合计 ¥xxx`

## 2. 统计（Stats）

两个子视图，顶部胶囊切换：**分类** / **节点**。
筛选栏：`分类/节点`、`清空`、`区间 / 年份 / 月份`。

- 选「月份」时 1–12 排成**一行**（`#nt-stats-pills[data-scope="month"]` 走 12 列栅格，
  390px 下每格约 28px、桌面容器上限 640px）；年份（个数不定）和区间（两个日期框）
  仍用默认 6 列，不吃这套规则。

### 2.1 分类视图

**两栏**（2026-11 改）：左栏 6 大分类表（默认 45% 宽，可拖），右侧一块「详情」。
栅格 `var(--nt-stats-left-w, 45%) minmax(0, 1fr)`；≤900px 一屏一栏横向吸附。
（原来是三栏、中右两块分类查询；2026-11 合成一块并改名「详情」，改由**点分类**驱动。）

**手机左右滑动切换「分类 / 节点」**（2026-11，`ui/stats-swipe.js`）：两个视图循环切。
规则：横向位移 ≥ 70px、且横向分量明显大于纵向（斜着划不动，免得滚动列表时误切）；
手指落点所在容器**真的能横滚**时不接管（列多或拖宽了要留给容器自己滚）。

**左栏 · 6 大分类**，顺序固定（2026-11 用户《统计功能规划》）：
`收入 / 负债 / 权益 / 资产 / 费用 / 成本`，从上到下顺着排，
**有内容才出一张表**（全零的类型整张不出现）。

**六张表结构统一为 5 列**：`第 1 列 | 4 个数值列`。数学只有两套（B 极小、A 极大），
费用是 A 极的变体，只差第 4 列。口径定义在 `core/stats-panels.js`。

| 类型 | 第 2 列 | 第 3 列 | 第 4 列 | 第 5 列 |
|---|---|---|---|---|
| 收入 | 期初累计 | 本期收入（转出） | 本期退回（转入） | 期末累计 |
| 负债 | 期初余额 | 本期新增（转出） | 本期偿还（转入） | 期末余额 |
| 权益 | 期初余额 | 本期增加（转出） | 本期减少（转入） | 期末余额 |
| 资产 | 期初余额 | 本期流入（转入） | 本期流出（转出） | 期末余额 |
| 费用 | 本期累计 | 本期支出（转入） | 本期退回（转出） | **本期净出** |
| 成本 | 期初净值 | 本期新增（转入） | 本期消耗（转出） | 期末净值 |

- **第 1 列**：五类都是「本期开始前」的状态，六类并排可比：
  - A 极（资产 / 成本）：`历史转入 − 历史转出`
  - B 极（收入 / 负债 / 权益）：`历史转出 − 历史转入`
  - **费用是例外**：`本期累计` = 到**本期结束**的累计净支出（转入 − 转出），
    正好等于资产类的「期末」。用户要的是「这类到今天一共花了多少」，
    所以它看的是累计而不是期初 —— 不叫「历史累计」。
- **第 4 列（期末）**：除费用外都是 `期初 + 增 − 减`。
  费用没有期末 —— 它报**本期净出** `本期支出 − 本期退回`；
  滚动关系：`本期累计 = 上期累计 + 本期净出`。
- 负债和应付同口径：转出=欠款增加、转入=欠款减少；正数=欠款，负余额=多还（显示「多还 ¥…」）。
- **没有序号列**（2026-11 删掉，手机放不下），也没有「节点」列（更早删掉）。
- **每类一张独立小表**：
  - 一张表 = 合计行 + 表头 + 该类的分类行；面板上原来的说明行已删；
  - 合计行在表头**上边**（`thead` 第一行，用 `<td>` 不是 `<th>`，否则表头数翻倍、列宽数组错位）；
  - 合计行：**分类列放类型名**（`资产`），金额列**只留数字**（不要「合计：」后缀），金额右对齐；
  - 合计行普通底色（透明）、**不画竖线**、加粗 13px；
  - 分类列内容居中；
  - 表与表之间空 24px，不画边框。
- **表宽 = 容器可用宽**：`.nt-stats-tables` 左右各留 12px，卡片与表格都是 `width:100%`，
  六张表宽度一致、上下对齐。手机 390 屏下 5 列正好排满，不需要横向滚动。
- **列宽只有两件事**：
  - **第 1 列宽度：分类和节点各一个参数**（2026-11）：
    分类 `分类统计/列宽` → `--nt-col-stat-cat`（默认 72），
    节点 `节点统计/列宽` → `--nt-col-node-cat`（默认 108）。
    节点名普遍比分类名长，共用一个默认值不是分类列浪费、就是节点名被截断。
    同类六张表读的是同一个值 —— 不是各存一份再同步。
  - **金额列**：**不写宽度**。`table-layout:fixed` 会把剩余空间**平均**分给
    没有宽度的列，所以「金额列自动等宽」不用 JS 算；拖分类列 = 改金额区总宽，四列自动重新均分。
  - **只有第 1 列有拖动手柄**，金额列没有。拖动实现是 `ui/stat-resize.js` 的**专用**一份
    （不走 `ui/table-layout.js` 那套通用的：它按坐标扫描整行表头、不检查手柄，
    会把 px 钉到「本来不该有宽度」的金额列上，看起来就是「点表头就错乱」）。
  - **点表头其它位置、点金额列，一律不改变任何列宽。**
- **合计行类型名前的彩色圆点**（2026-11）：标的是**类型**（收入 / 负债 / 资产 / 费用 / 权益 / 成本），
  不是每一行的分类名 / 节点名。颜色取环图的外层固定色系
  （`graph/mw-layers.js` 的 `typeColor`：费用红 / 资产蓝 / 收入绿 / 负债橙 / 权益紫 / 成本灰）。
- **字号可整体缩放**：`分类统计/列标字号`（默认 12）、`分类统计/数据字号`（默认 14）。
  低分辨率手机上放大这两项即可；它们是七张统计表共用的，不走「每表一套尺寸」。
- **分类 / 节点名可以点**（2026-11）：点了右侧「详情」就列出构成它的流水；
  当前正在看的那一行左侧留一道前景色细条（`aria-selected="true"`）。
- **合计行样式**（2026-11）：行高 `29px`（= 26 × 1.1）；金额格**靠右下**
  （`text-align:right` + `vertical-align:bottom`，字号 13）；类型名格**靠左居中**
  （`text-align:left` + `vertical-align:middle`，字号 14，比金额大一号）。
- **金额显示**（2026-11）：统计小表里的金额一律**1 位小数、不带 ¥、不带千分位**
  （`core/format.js` 的 `statAmount`，固定 1 位）。纯整数试过 —— 核对时差那几毛钱对不上账；
  两位又太宽，手机上 5 列挤不下。固定 1 位还能让整列小数点对齐。
  负债的负余额仍标「多还」（`多还 300.0`）。
- **值为 0 的格子只调字体颜色**（`color-mix` 把文字色往背景混 38%），**不用 opacity**：
  透明度作用在整个 td 上，会把单元格边框一起淡化，网格断成一截一截。
  边框色另外显式钉住（`border-color` 默认取 `currentColor`，文字一变色线就跟着变）。
- **字号自适应**（2026-11）：每张表渲染后按「最长内容 ÷ 实际列宽」估算一次，
  放不下就把**这张表**的数据字号收窄（下限 9px），写到表级 `--nt-stat-font-fit`；
  放得下时不设这个变量，回到参数里的基础字号（`分类统计/数据字号`）。
  实现在 `ui/stat-fit.js`：估算而不是逐格测量 —— `scrollWidth` 在
  `table-layout:fixed` 的 td 上不可靠（td 不是滚动容器）。
- **每张小表的顺序可自定义**（2026-11）：合计行的类型名后面有个小 ▲，
  点它这张表往上挪一位（`ui/stat-order.js`）。顺序存在 localStorage ——
  它和「左栏宽度」一样是界面偏好，不进加密账本。分类视图和节点视图共用同一份顺序。
- ▲ **不参与单元格流布局**（`position: absolute` 钉在类型名格右侧，格子
  `overflow: visible` + 留 16px 内边距）—— 分类列调窄时它不会被 `ellipsis` 裁掉。
- 全零分类默认隐藏；分类按**期末（费用按净出）绝对值**降序。

### 2.2 详情（原「分类查询」）

**一块**（2026-11）：标题「详情」，中右两块合成一块，第二个查询面板取消。
两种驱动方式，结果一样：

1. **点左栏的名字** —— 点「餐饮」就把 `餐饮` 灌进输入框并立刻列出这一格的钱，
   被点的那行左侧亮起一道细条；
2. **手打** —— 填分类名（`储蓄`）或拼音首字母（`cx`），规则与点击完全一致。

- **标题、输入框、清空在同一行**：标题在左，输入框 + 清空**靠右排列**；
  输入框与按钮同高 26px；输入框占 **1/3 宽**（用户 2026-11）。
- **输入字母就弹出候选**：打 `c` 弹出 `cx 储蓄` / `rc 日常`，点一项直接带入分类名并查询
  （候选按「首字母全等 > 首字母前缀 > 名字前缀 > 其它」排序，同档节点多的在前）。
- 回车：能精确命中的唯一分类会带回全名（`rc` → `日常`）；只弹出一个候选时也直接选它；
  多个候选则保持原输入继续筛。
- 时间段：跟当前统计范围一致（月份 / 年份 / 区间 / 全部）；
- 命中：一笔流水只要**转出方或转入方任一账户的分类**命中（名字包含或首字母包含），就列出；
- 列：`序 | 日期 | 转出 | 转入 | 金额 | 备注`（**序** = 这条流水在流水表的行号），日期倒序；
- **前 5 列居中**，备注**靠左**；备注列**不写宽度**，吃掉剩余空间 ——
  它的右边缘因此始终贴住面板右边（实测差 1px，正好是面板那道 1px 边框）。
- **点备注弹气泡**：备注格挂 `data-field="note"`，由 `ui/note-popover.js` 处理 ——
  和流水表 / 流水查询表**完全是同一套**（`app.js` 里已经全局绑过一次，这里不需要再绑）。
  窄屏放不下整段备注时，点一下在旁边看全文。
- 标题行的输入框：**占满剩余宽度**、背景透明（平时无框，焦点才出一条主色底线）、
  **输入内容居中**。
- 底部状态栏显示「详情「储蓄」N 笔」。

> 首字母不是查表：用 `Intl.Collator('zh')` 的拼音排序和 23 个「字母代表字」比大小，
> 定位汉字落在哪个字母区间（见 `core/pinyin.js`）。生僻字落在拼音区之外时返回空串，
> 自动退回名字匹配，不会算错。

### 2.3 节点视图

**布局逻辑完全沿用分类表**（2026-11 用户指定）：同样是「左 6 类表 + 右详情」的两栏栅格、
同样的分界条、同样的列宽参数（`分类统计/列宽`，七张表共用一个值）、同样的合计行样式。

- 左栏第一列是**节点名**，后 4 列与同类型的分类表**逐项相同**（同一个 `statCells`）。
- **点节点名** → 右侧「详情」列出该节点的流水（`queryByNodes`，按 `account.name` 匹配）；
- **详情输入框认简码，而且能一次填多个**（2026-11）：
  输入 `ZHC` 会就地换成节点名「招行储」；`ZHC XJ`、`ZHC，XJ`、`ZHC,XJ`、`ZHC.XJ`
  都算两个 —— 空格、中文逗号、英文逗号、点都是分隔符。
  识别出来的名字用「，」连起来填回输入框，表格里同时显示这几个节点的流水（合并去重、日期倒序）。
  认不出的词原样保留，仍然按节点名做包含匹配（所以直接打名字也照常能用）。
- 节点详情**不认拼音首字母**（用户 2026-11）：它靠简码定位，再叠一层首字母匹配
  会互相误伤（简码 `ZHC` 恰好也是「招行储」的首字母）。分类详情仍然认首字母。
- 数据来自 `nodeStats()`，口径与 `categoryStats()` 完全一致 —— 只有聚合维度不同，
  分类视图是 `acc.category`，节点视图是 `acc.name`。
- 列名随类型变，和 §2.1 的对照表一模一样（只是把「分类」换成「节点」）。
- 组内按期末（费用按净出）绝对值降序，同额按名称排。
- 无数据的行不占位置；整类无数据不出表。
- 所有金额只读。

## 3. 查询（Query）

**列标**：`序 | 日期 | 转出节点 | 转入节点 | 金额 | 备注`（6 列，不冻结）

- 条件：日期起止 / 转出 / 转入 / 金额 / 备注（多条件联合）
- **转出、转入回车（或失焦）才筛选**，输入过程中不重画：
  打简码时每按一个键就筛一次又闪又慢，而且替换时机取决于打到第几个字符。
- **转出、转入填同一个节点** = 该节点的「转出 + 转入」一起列（不是「与」）：
  - 一笔流水不可能自己转给自己，两栏同值时按「与」筛永远是 0 行；
  - 写法不同但指向同一账户（一个打名字、一个打简码）也算同一个节点；
  - 时间段留空 = 该节点的全部流水；填了 `261101~261130` 这种就只留区间内。
- **简码在回车后变成节点名字**：在转出 / 转入框里打完 `ZHC` 再回车，框里变成「招行储」。
  只在名字全等或简码全等时替换 —— 打「招」不会被补成「招行储」，否则没法再做模糊搜索。
- 结果按**日期升序**（同一天保持录入顺序），因为同一个节点的转出/转入合在一起看时，
  录入顺序是乱的。
- 底部联动统计：`A: 37 笔 ¥74.00 · B: …`
- 备注被省略号截断时，点击弹层看全文
- 三段独立查询表，表单状态与渲染分离；查询逻辑在 `core/query-engine.js`

## 5. 计划（Plan）= 固定收支 + 分期

> **整合原则**：分期是固定收支的**子模块**。
> 分期表是**交互界面**，固定收支是**计算聚合接口**。
> 底层统一为「计划流水」：固定收支无 `inst` 字段，分期带 `inst`。

顶部两个子视图胶囊：**固定收支** / **分期还款**。

### 5.1 子视图 A：固定收支

**列标**：`序 | 频率 | 日期 | 转出节点 | 转入节点 | 金额 | 备注`　**冻结**：序

- 频率下拉：每天 / 每月
- 日期：几号（每月）或起始日（每天）
- **每月到期自动落成真实流水**；每日不自动，流水页只显示**当天一条**虚拟行，点 ▲ 才生效
- 自动落账的备注取固定表模板备注；模板为空就为空（非分期不补「第几期」）
- 固定表选「每天」时，日期格显示横线且不可录入；切回「每月」恢复几号输入
- 自动落的那笔可像普通流水一样修改 / 删除；删掉后这一期不再自动补
- 末尾固定 **10 个空行**：不显示默认「每月」，日期/金额格也不放占位文字，整行留白
- 转出 / 转入格可以写账本里没有的新节点名；保存时自动补成空类型的「未分类」节点
- 一行填完、**离开这一行**才建规则（金额填完点同行备注不算离开，备注不会被抢建）
- 行内直接编辑；**每次编辑只更新单一字段，不触发全局重绘**
- 顶部聚合：`每月收入合计 / 支出合计`（由 `getSchedulerSummary` 算）

### 5.2 子视图 B：分期还款

**列标**：`节点名称 | 分期金额 | 账单日 | 还款日 | [未来月份1] | [未来月份2] …`
**冻结**：节点名称（横向滑动时左侧不动）

- **双行一条记录**：上行为本金，下行为利息
- 新增 / 复制按钮 → 弹窗录（期数、首月、本金、利息）
- 起止月份输入（`2608`）控制矩阵范围
- 只读展示（数据来自分期规则，不在此处改金额）
- 顶部聚合：`未还本金合计 / 未还利息合计`

### 5.3 数据模型统一

```js
// 固定收支
{ id:'sched_01', isScheduled:true, freq:'monthly', day:25, from_id, to_id, amount:900 }
// 分期 = 固定 + inst
{ ...同上, amount:1060, inst:{ periods:12, firstMonth:'2026-08', principal:12000, interest:720 } }
```

引擎：`core/scheduler-engine.js`（`generateFutureFlows` / `getSchedulerSummary` / `projectMonthlyCashflow`）。

**虚实结合**：在时间轴上选某个月时，真实流水 + 该月虚拟流水混合显示，
虚拟行用虚线边框 / 半透明，让用户一眼分清「过去的钱是真钱，未来的钱是虚钱」。

### 6.1 账户列表

**列标**：`简码 | 序 | 类型 | 分类 | 节点名称 | 期初 | 账单日 | 还款日 | 上移 | 删除`
**冻结**：只冻结首列「简码」+ 首行表头（像 Excel 的冻结首列 + 冻结首行）。
不冻结第二列 —— 序列跟着横滚。

- **期初方向**：资产 / 费用 / 成本 = `期初余额 → 账户`；负债 / 权益 / 收入 = `账户 → 期初余额`。

- 末尾固定 **10 个空行**（在 U 区之后、备注区之前）；建行时按填写的类型自动归 A / B / U。
- 空行填了「名称」就成一个新账户；类型留空按资产类。

  { qr, donors:[…] }                   { v, salt, iv, ct }（base64）

**管理界面**（v1.84 加）：`nt/thanks-admin.html`

- 线上 `https://jefely.github.io/money-way/nt/thanks-admin.html`

- **离线**：解密结果缓存 `localStorage['nt_thanks_cache_v1']`；拉不到 / 解不开时用缓存，
