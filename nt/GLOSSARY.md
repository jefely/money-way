# NT账本 · 术语表（Glossary）

> **这份文件存在的唯一理由**：避免「账户类型」和「统计分类」被混为一谈。
> 2026-10 的一次实现里，我把颜色键写成了 `类型|分类`，导致同一个统计分类在两个类型下拿到两种颜色。
> 那不是一个笔误，是**没先分清这两个概念**。所以这里把它写成定义，摆在最前面。

---

## ⚠️ 两个必须分清的概念

| | **账户类型**（type） | **统计分类**（category） |
|---|---|---|
| **用途** | **计算**（决定加减方向） | **统计与显示**（分组、着色、报表） |
| **取值** | 资产类 / 负债类 / 权益类 / 收入类 / 费用类 | 储蓄 / 信用 / 日常 / 餐饮 / 交通 / 现金 … |
| **谁在用** | `balance-calculator.js`、`validator.js`（V6 恒等式） | 统计表分组、Money Way 的**颜色**、查询筛选 |
| **能否为空** | 否（五选一，非法值归一为资产类） | 可以（归为「未分类」） |
| **改动影响** | 改类型 = **账目语义变了**，余额会跟着反号 | 改分类 = 只是换个标签，**不影响一分钱** |

### 一句话记法

> **类型管「钱怎么加减」，分类管「东西怎么归类」。**
> 类型是计算逻辑，分类是统计标签。

### 常见的三个误用

| 误用 | 后果 |
|---|---|
| 用分类做加减判断 | 「餐饮」是费用 → 但「餐饮储值卡」是资产，一刀切就错了 |
| 用类型做颜色 | 颜色数 = 类型数(5)，全图只有 5 色，分类的信息全丢了 |
| 用 `类型\|分类` 当颜色键 | 同一分类被类型拆成多色（**这就是我犯过的错**） |

## 数据结构里的对应字段

```js
{
  id: 'acc_01',
  code: 'JHC',           // 简码：输入用的马甲
  name: '交行储8380',     // 显示名
  type: '资产类',         // ★ 账户类型：计算用
  category: '储蓄',       // ★ 统计分类：统计/着色用
  isHidden: false
}
```

流水只存 `from_id` / `to_id`，**不存类型也不存分类** —— 它们随时可以从账户表查出来。
所以改类型/改分类都不需要动历史流水。

## 其他容易混的术语

| 术语 | 定义 | 不要与…混淆 |
|---|---|---|
| **简码（code）** | 2~5 位大写字母/数字，输入时用的快捷方式 | 不是外键，流水里永远不存简码 |
| **期初（opening）** | 账本开始时的状态，落地为一条对手方是 `__OPENING__` 的流水 | 不是账户的一个字段（v2 起已迁移成流水） |
| **计划流水** | 固定收支与分期的统称，只存规则、不存结果 | 不等于虚拟流水（虚拟流水是它算出来的投影） |
| **虚拟流水** | `generateFutureFlows()` 算出来的未来投影，带 `isVirtual` | **永不写进 `state.transactions`** |
| **细粒度单位** | 一笔流水在环上占 2 个单位（转出端 + 转入端） | 不等于「笔数」，也不等于「金额」 |
| **sortKey / colorKey** | 排序键 = `类型\|分类`；颜色键 = **只有分类** | 两者绝不能合并成一个键 |

---

## 写代码前的自检

- 我要判断加减 → 用 `type`
- 我要分组/着色/筛选 → 用 `category`
- 我要找账户 → 用 `id`（输入时允许 `code` 或 `name` 解析成 `id`）
- 我要显示 → 用 `name`

**四件事，四个字段，不许串用。**
