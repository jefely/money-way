# 单文件版 → nt/ 功能对照

> 目的：回答一个问题 —— **`nt/` 还差什么**。
> 对照对象：`personal/index.html`（19837 行，用户日常在用的成熟版）↔ `nt/`（`nt-v1.129` 之后）。
> 口径：只列**用户能触发的功能**，不列内部实现差异。实现换了但用户看到的效果一样，算「已搬」。
>
> 这份表是**一次考古的结果**，不是永久真相。补掉一条就改那一行；
> 新增的 nt 功能**不要**往这里加 —— 这里只记「欠单文件版的」。

图例：✅ 已搬 · 🔁 换了实现（效果等价）· ⚠️ 部分 · ❌ 没有 · 🚫 有意不做

## 二、迁移通道（单文件版 → nt）

这是**最要紧**的一节：用户手上只有单文件版的数据，搬不过来就等于 nt 白做。

单文件版有两条出口：

| 出口 | 内容 | 2026-10-30 之前 | 现在 |
|---|---|---|---|
| 导出 `.lz` | `{v:3, accounts, transactions, installments, fixed, installState}` | ❌ 只读 `scheduled`，而单文件版**不导出** `scheduled` → 固定收支与分期**静默丢失** | ✅ 已修 |
| 导出 `.xlsx` | 4 张表，账户表叫**「汇总」**，13 列 | ❌ 只认「设置」表名，且按固定列位读 → 单文件版导出的文件根本不会被当成备份 | ✅ 已修 |

### ✅ `.lz` 的 fixed / installments（v1.130 修）

`core/lz-file.js` 的 `stateFromLzPayload` 现在认三种形状：本工程的 `scheduled`、
单文件版的 `fixed`（固定收支）、单文件版的 `installments`（分期矩阵）。

分期是**反向推**过去的 —— 单文件版没有「期数 / 首月 / 利息」这三个字段，它们是矩阵的属性：

```
periods     = 有值的月份个数
firstMonth  = 第一个有值的月份（2610 → 2026-10）
principal   = 各期 p 之和
interest    = 各期 i 之和
to_id       = 那张卡的账户（按名字匹配）
billDay/day = 账单日 / 还款日
```

**一处不可逆的损失**：单文件版允许每期本金不等（手填），本工程按均额摊。
总额一定对得上，单期金额可能对不上。导入对话框会显示「有 N 条没能搬过来」，
但**不会**告诉你「某几条的每期金额变了」—— 因为那在这套模型里无法表达。

### ✅ `.xlsx` 的「汇总」表（v1.130 修）

- `core/xlsx-template.js` 的 `pickTemplateSheets`：账户表叫「设置」或「汇总」都算整本备份。
- `core/xlsx-template-read.js` 的 `parseSettingsRows`：**先按表头文字定位列**，找不到表头才退回固定列位。

为什么要改：两张表的列序完全不同 ——

```
单文件版「汇总」：序 类型 分类 简码 账户名称 当前结余 转出 转入 转出历史 转入历史 期初 账单日 还款日
本工程「设置」  ：简码 序 类型 分类 账户名称 期初 账单日 还款日
```

按固定列位读 13 列的表，会得到「简码 = 序号、类型 = 分类、**期初 = 当前结余**」——
每条都错，而且界面上完全看不出错（导入成功、数字都在，只是全是错的）。
这正是「宁可多写 30 行按表头解析」的理由。

另外补了一条：单文件版的**类型小计行**（账户名称列写「资产类」，其余三列空）要跳过，
否则会多出一个叫「资产类」的假账户。

其余三张表（流水 / 分期 / 固定）的列序本来就一致，不用改。
流水表的日期写的是 `YYMMDD`（如 `261022`），`parseBillDate` 已经认。

## 三、其余缺口

按「用户多久会撞上」排序。

### 1. 账单导入不判重 ❌

**单文件版**：多重集判重。按 `txFingerprint` 统计本机已有各指纹的次数，本批按次数抵消；
另把 `billId/tradeNo` 放进 `seenBill` 集合再判一次。重复的**照样导入**，但 toast 里报「重复 N 笔」。
注释说明了为什么不能用 Set：「同名同日同额的多笔是合法的（招行只有日期、没有单号，
一天里同一商户刷两次很常见）…既不会把真实的两笔吞成一笔，重复导同一份也不会翻倍。」

**nt**：`core/import-table.js` 里 `billFingerprint` / `existingFingerprints` **写了但没人调用**；
`views/flow.js` 的 `importItems()` 直接逐条 `addTransaction`。同一份账单导两次就是两倍流水。

**成本**：小。判重是纯函数，`importItems` 里调一次并计数。测试能完全覆盖。

### 2. 固定收支不会自动写进流水 ❌（**需要你裁决**）

**单文件版**：`runFixedExpenses()` 在打开页面时跑一次，每账本每天最多一次
（run-key 按账本分开），5 点之前不跑。到期条目真的写进 `state.transactions`，
带 `fixedId` 回指，并回写 `lastMonth` / `lastDate`。「每月 31 号」在 30 天月和 2 月自动钳到月末。

**nt**：`core/scheduler-engine.js` 只生成**虚拟流水**（`isVirtual: true`），注释明确写
「永远不会混进 state.transactions」。固定表也没有「本月状态」列。

这不是 bug，是两种产品立场：
- 单文件版：到期就记上，用户事后核对。
- nt：未来是预测，账本里只留真实发生过的。

**需要你选**：nt 要不要也自动入账？要的话 `lastMonth/lastDate` 与 run-key 的账本隔离都要照搬；
不要的话固定表的「本月」列也不必加。

### 3. 重置只有「清空」一档 ❌

**单文件版**：先二选一 ——「重置账户（保留数据）」（只换账户表，流水/分期/固定全留）/
「重置账本（清空数据）」。两档都要**键入「重置」**才能点确定。

**nt**：只有一个「重置账本（清空）」，没有输入确认，点两下就没了。

**成本**：小。`resetAll` 已经在 `ctx` 里，加一个 `resetAccounts` 分支；
「键入重置才启用」十几行 UI。

### 4. 提取流水账户 ❌

**单文件版**：账本说明页底部一个按钮 —— 扫出流水里出现过、账户表没有的名字，
逐个追加为账户（简码自动给 X1、X2…，类型默认资产类），提示去汇总页校对。

**nt**：没有这个入口。`core/account-resolver.js` 的 `ensurePendingAccount` 会在**导入时**
自动建一个「待分类」账户兜底 —— 这挡住了「导入丢数据」，但没解决「账户表里缺一批名字」的清理需求。

**成本**：小到中。扫描 + 追加是纯函数；UI 一个按钮。要和「待分类」协调（否则会重复）。

### 5. 全局撤销（Ctrl+Z）❌

**单文件版**：每次 `save()` 且 JSON 有变化就把上一状态压栈（`UNDO_MAX=20`），
焦点不在输入框时按 Ctrl/Cmd+Z 整体回退。在输入框里**不抢**，交给浏览器。

**nt**：只有删除后的 8 秒撤销条（`ui/undo-bar.js`），覆盖流水/固定/分期三种删除。
改错一个金额、改错一个账户名，没有后悔药。

**成本**：中。要在 `app.js` 的 `setState` 上挂快照栈（注意别把 40 个空行也算进去），
再绑一个 window keydown（跳过 INPUT/TEXTAREA）。风险是内存。

### 6. 长备注看不全 ❌

**单文件版**：查询结果里备注被省略号截断时，**点一下**弹浮层显示全文；
浮层右缘对齐格子右缘向左展开，点别处或 Esc 关闭。只在 `scrollWidth > clientWidth` 时才弹。

**nt**：流水表备注格也是截断的，没有任何查看全文的入口。

**成本**：小。一个浮层 + 一个 click 委托。

### 7. 两处键盘习惯 ⚠️

- **Enter 跳到同列下一行**：单文件版在任一格按 Enter，沿 `tr.nextElementSibling` 找同名字段并 `focus()+select()`；
  nt 的 Enter 只是「blur + 提交」。
- **日期栏输入 `:` 取今天**：单文件版在所有日期输入框都支持；nt 的 `normalizeDateInput` 只认 6 位 / 8 位数字。

**成本**：都很小，但会碰 `row-editor.js` 的提交时机 —— 改前先量（别把「失焦建单」弄坏）。

### 8. 账本说明偏简 ⚠️

单文件版有六段：简介 / 简单开始 / 账户性质表 / 两条校验 / 三个时间区域 /
**虚拟账户**（为什么要有「收入汇总」「实收资本」）/ **数据自持与备份**（PBKDF2→AES-GCM、
忘记密码=永久丢失、会被清掉的情形、换手机前先存同步文件）。

nt 的 `views/validate.js` 缺最后两段 —— 而这两段恰恰是新用户最该读的。**纯文字，几分钟。**

### 9. 同步不能从图片读码 ⚠️

单文件版用 `BarcodeDetector` + `createImageBitmap` 从截图里读二维码；nt 只有「粘贴文本」通道。
手机上「从相册选图」这条路走不通。成本小（有 API 就用，没有就隐藏按钮），
但 `BarcodeDetector` 在桌面 Chrome 里默认不可用，别指望它。

### 10. 固定收支没有「本月状态」列 ⚠️

单文件版有「已写入 / 待写入」一列。它与第 2 条同一根：不做自动入账，这一列就没有意义。

## 四、有意不同，不要照搬

| 项 | 单文件版 | nt | 为什么不要照搬 |
|---|---|---|---|
| **分期** | 手填矩阵：一条占两行，每期本金/利息自己填 | 引擎推算：本金 + 期数 + 利息 + 首月 | 手填矩阵没有「期数」概念，改期数不重算；nt 的模型能算剩余本息。**但用户习惯哪一种要问** |
| **统计列** | 分类 5 列 / 汇总 9 列 | 分类 8 列 / 汇总 10 列（都带历史三项） | nt 多出来的列有用，不是膨胀 |
| **导入入口** | 两级菜单：备份 / 账单 | 一个入口，自动识别（4 表模板 / .lz / 账单 / 通用表 / 手动指定列） | 自动识别已经是超集 |
| **框选** | 没有 | 有（`ui/cell-range.js`，长按起手 → 拖动 → 复制/粘贴/删除） | nt 独有 |
| **V1–V7** | 没有编号，只有三张卡 | 有编号 + 明细列表 | nt 独有，可追溯到具体问题 |
| **流水长列表** | 「还有 N 笔没显示」+ 点击/滚动加载 | 虚拟滚动（只渲染可视区） | nt 在 2 万笔时更稳 |
| **路径图取数** | 独立日期区间 | 由左栏五个筛选框决定 | 用户 2026-10 定过「图的统计范围完全由左边筛选决定」 |
| **同步分页** | 「每张 N 笔」手调 | 自适应窗口（按天装满，70 笔封顶） | 用户 2026-10-29 定稿 |
| **xlsx 账户表名** | 「汇总」（13 列） | 「设置」（8 列） | 列少了 5 个金额列（设置页不需要）；导入侧已双向兼容 |

## 五、单文件版里的死代码（不必搬）

考古时发现这些函数还在、但**没有任何调用点**：

| 函数 | 状态 |
|---|---|
| `openRowMenu` | 定义了行菜单，全文无调用 |
| `openHelpDialog` | 「账本说明」弹窗，已被校验页分页取代 |
| `openAuditSummaryDialog` | 体检汇总弹窗，已被内联三张卡取代 |
| `openVersionDialog` | 版本弹窗，已被账本说明页的「更新」按钮取代 |
| `openThanksDialog` | 赞助弹窗，已被「赞助感谢」分页取代 |
| `ensurePendingAccount` 的注释 | 注释说「认不出来的账户先落到待分类」，但账单导入路径**不调用它**，实际是留空 |
| 改密码的「提示词」输入框 | 提交时根本没被读取（`go.onclick` 只用三个密码框） |
| `catMode==='all'` 分支 | 代码里有，但 bar1 从不渲染「全部」按钮，用户靠「清空」达到同样效果 |

## 六、怎么维护这份表

1. 补掉一条缺口，就把那一行改成 ✅ 并注明版本号（例：`✅ v1.130`）。
2. 新增的 nt 功能**不要**往这里加 —— 这里只记「欠单文件版的」。
3. 每次大改 `personal/index.html` 后，只需要重看对应那一页的行。
4. 第 2 条（固定收支自动入账）和「分期模型」是**产品立场**，不是实现细节；
   改之前先问用户，别自己定。
